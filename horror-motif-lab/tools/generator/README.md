# 场景生成器（gen.py）

把《恐怖美学八母题复用公式卡》的母公式做成可执行程序：

```
T = (R − e₁) × Δ − I − E
```

## 环境

- Python 3.8+，**纯标准库，零依赖**
- 本机实测：`E:\Python314\python.exe`（3.13.14）
- Windows 控制台已内置 UTF-8 reconfigure，中文不会乱码

```bash
cd tools/generator
python gen.py list
```

## 命令

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `list` | 列出八母题、每条的 Δ 与支持温度、五档温度定义 | `python gen.py list` |
| `gen` | 生成一张场景卡 | `python gen.py gen -m 怨灵 -t 关系型 --seed 42` |
| `batch` | 批量生成，可写入文件 | `python gen.py batch -n 8 --seed 2026 -o cards.md` |
| `check` | 只跑结构自检，不排版 | `python gen.py check -m mirror -t 关系型` |
| `matrix` | 打印母题 × 温度兼容矩阵 | `python gen.py matrix` |

**母题参数支持口语**：`鬼 / 怨灵 / 幽灵` 都能命中 `幽灵与怨念`；`阈限 / 走廊 / 后室` 命中 `禁地与废墟／阈限空间`；也可以直接写 id（`ghost`、`liminal`）。

**温度参数支持简写**：`温/关系`、`冷/系统`、`黏/身体`、`史诗/崇高`、`狂喜`。

**e₁ 强度**：`--strength low|mid|high|any`，默认 any。

## 确定性

同一个 `--seed` 必然产出逐字节相同的卡，可用 `diff` 对账：

```bash
python gen.py gen -m liminal -t 系统型 --seed 7 > a.txt
python gen.py gen -m liminal -t 系统型 --seed 7 > b.txt
diff a.txt b.txt   # 无输出 = 一致
```

`batch --out` 会打印复现命令，照抄即可重跑同一批。

## 三条硬约束（生成器的价值全在这里）

普通的"素材拼接器"会把任何两句话塞在一起，输出看起来完整但逻辑断裂的废卡。本生成器强制三条约束，任一条不满足就在自检里报 ❌：

### 1. R 与 e₁ 必须同频道

每条 e₁ 带 `pair` 标签，每条规程带 `cat` 标签；生成时只从 `cat ∈ pair` 的规程里取。否则会写出「在本来**纸钱要烧透**的地方，只有**下摆不动**不对」这种句子——公式被随机组合打穿。

### 2. ★ 符号必须是 e₁ 自己的载体

每条 e₁ 自带 `sym` 字段（通道 + 文本），生成时直接升为 ★，不再从符号库里"挑一个去承载"。所以 ★ 永远真的承载 e₁，不是装饰。

### 3. 温度不兼容必须拒绝

`幽灵与怨念 × 系统型` 是不成立的组合（系统型不承认账本存在）。生成器会退回该母题的首选温度并给出警告，`check` 会返回退出码 2 明确"不应投入生产"。

## 自检项

| # | 检查 | 失败含义 |
| --- | --- | --- |
| 1 | e₁ 唯一 | 结构上只选一条一错 |
| 2 | 符号跨通道且 ★ 是 e₁ 载体 | ★ 与 e₁ 不同源 |
| 3 | R 规程 ≥2 条且带证据档位 | 规程不可复述 |
| 4 | E 出口已指定 | 缺出口 |
| 5 | 温度与母题兼容 | 组合不成立 |
| 6 | 信息阶梯 = 3 段 | 违反"三次上限" |
| 7 | e₁ 强度分级提醒 | 位置建议 |
| 8 | R 与 e₁ 配对 | 骨架逻辑断裂 |

## 生成器不做什么

它**不替你判断**这三件事（每张卡末尾都列出来了）：

- **I 阶梯是否与所选 e₁ 同源**：数据里的 `info_ladder` 是母题级示例（"设备故障→有人潜入→自己记错"），换了 e₁ 就要按同样的三推结构重写。
- **是否还有第二处异常**：一错律要求全篇唯一，生成器只保证这一条，管不了你在正文里手滑加的第二个。
- **出口是否被写死**：给了"彻底解决"，怨念立刻降格为怪物。

## 加新母题

编辑 `motifs.json`，往 `motifs` 数组里加一项，必需字段：

```json
{
  "id": "spider",
  "name": "蛛形与寄生",
  "delta": "体内／体外",
  "layer": "内容",
  "core": "一句话核心命题",
  "temps": ["身体型", "系统型"],
  "rules": [{"t": "规程条目", "cat": "类别", "tier": "A|B|C"}],
  "checks": ["角色日常检验动作"],
  "errors": [{
    "t": "一错", "layer": "物质|社会|道德", "strength": "low|mid|high",
    "note": "用法提醒", "pair": ["可承接的 cat"],
    "sym": {"c": "通道", "t": "该 e₁ 的载体"}
  }],
  "exits": {"身体型": "…", "系统型": "…"},
  "symbols": [{"c": "通道", "t": "氛围符号", "cat": "类别"}],
  "info_ladder": ["第一推", "第二推", "第三推"],
  "anti": ["专属反模式"],
  "scenes": [{"r": "…", "e1": "…", "scene": "…"}]
}
```

加完跑一次全组合压测：

```bash
python -c "import gen,random; d=gen.load_data(); [gen.build_card(d,m,t,random.Random(s)) for m in d['motifs'] for t in m['temps'] for s in (1,2,3)]; print('OK')"
```

`errors[].pair` 里的每个 cat 都必须能在该母题的 `rules[].cat` 里找到，否则该 e₁ 无法配对规程。

## 已知局限

- **中文分词无**：母题匹配是别名表 + 子串，不做分词。
- **不生成叙事**：输出的是参数卡与骨架，不是场景段落。要成段落得靠人（或另写生成层）。
- **e₁ 池有限**：每个母题 10 条，反复跑会重复。要新鲜感就扩池，不要改随机数。
- **温度互斥是硬编码**：`temps` 字段写死支持列表，没有推导逻辑。这是有意的——它代表判断，不该被算法自动推断。
