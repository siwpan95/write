## 二、联网检索补入的三类信息

### 1. 破产法庭实务（第一章场景真实度）
- **债权表**由管理人编制（《企业破产法》第 57 条），提交**第一次债权人会议核查**（第 58 条）；有异议的十日内评议、裁定书经审判长审核报庭长签发
- 第一次债权人会议标准程序：**书记员宣布纪律 → 审判长通报到会情况 → 管理人作执行职务报告 → 核查债权 → 表决**（云浮/中山/厦门法院审理规程）
- **表决票编号须与债权表编号一致**；决议须有表决权债权人**过半数通过且债权额占无担保总额 1/2 以上**（第 64 条）——正文第一节会议全部按此程序书写

## 七 作家助手导入版合订 TXT（2026-11-12）

**背景**：作家助手导入只支持 txt / word，逐章手动导入太慢，故出 `02-正文/法则权能-正文合集.txt` 合订版。首版导入后容易打乱章节，本轮按作家助手真实导出物重排该合订版。

**格式依据**：`其他项目归档/战锤42：拔智齿-第一卷 鲜衣怒马少年时.txt`（作家助手导出的正文，UTF-8 无 BOM + CRLF）。实测形态对照：

| 项 | 参考导出物 | 首版合订版（问题） | 本版 |
|---|---|---|---|
| 文件头 | 卷名单独一行 | 6 行元信息 + `【目录】` + 202 条 `· 章名` | 书名 `法则权能` 单独一行 |
| 章节标题 | `第1章 少年`（阿拉伯数字、行首） | 两条 `════` 夹「第一章 · 第十三条」 | `第1章 第十三条` |
| 段落 | `　　` 全角缩进、段间无空行 | 无缩进，含 `————`、`· `、表格 | 全角缩进、零空行 |
| 非正文内容 | 无 | 8 篇设定资料 + 章首索引卡台账 | 一律不进正文 |

**乱章根因（五条）**：① 目录 202 行含章名，会被按「第X章」误切为章节；② 章名用中文数字且被装饰线包裹，识别不稳；③ 8 篇无章号资料夹在主线之间，会被并入相邻章；④ 章首 `## 本章索引卡` 台账行以 `- [x]` / `第X节` 起头，易被当结构行；⑤ **导入器遇行首「第」即切章**（作者实测，详见下文「导入器实测补充」）。

**本版规则**：

- 194 章：`第0章 序章 膜` + `第1章`~`第193章`，章号与原书**一一对应**（中文数字→阿拉伯数字；已核验 1..193 严格连续），导入后无需给任何一章改名。序章编 `第0章` 只为让平台单独切出一章，导入后可改名为「序章」。
- 正文按源文件名数字前缀顺序排列；每段 `　　` 缩进，段间不留空行，不出现目录、分隔线、Markdown 残留与元信息头（`工作区规范.md` §六「正文文件只含标题行 + 纯正文」）。
- 8 篇非章节资料**不并入导入版**（源文件仍在，零丢失）：`07-路径树-分岔总图.md`、`08-分支短章-三条岔路.md`、`10/12/14/16/18-支线POV集-卷一~卷五.md`、`19-索引卡-卷一终章与卷二.md`。需要一并导入时用 `--include-appendix`，它们按原顺序追加为末尾 `第194章 附录 …`~`第201章 附录 …`，章号仍连续。
- 章首 `## 本章索引卡` 台账块在**导入版副本**中整体剔除；**源 `.md` 仍按上文「保留原则」原样保留**（两处口径不冲突：副本是发布文本，源文件是流水线骨架）。
- 编码：入库版 UTF-8-SIG + LF（仓内规范）；参考导出物是 UTF-8 无 BOM + CRLF。如需完全对齐平台，用 `--crlf --out <路径>` 另出交换副本，**不要提交入库**；复跑默认参数即可还原入库版。

**导入器实测补充（作者 2026-11-12 复测）**：作家助手导入非常机械，**任何一行只要去空白后以「第」起头，就被当成独立章节**，不限于「第N章」。按此规则全量扫描导入版，命中 **271 行 / 109 章**（「第三天…」「第七节…」「第 1 版…」「第一百章。板走到了第四步——清。」等），都会被切成伪章节。

**防误切加字**：所有非标题、行首为「第」的段落，在 `　　` 缩进后、正文前统一加一个前缀字，默认间隔号 `·`，即 `　　· 第三天，裂缝开始生长。`。平台去空白后看到的第一个字符不再是「第」，即不会误切。这是**纯排版转义**：源 `.md` 一字未改，去掉「前缀 + 空格」即可逐字回溯原文；`--guard '※'` 可换成更独特、便于导入后批量查找替换的符号，`--no-guard` 可关闭（仅用于核对原文，勿拿去导入），`--guard` 为纯空白时脚本会告警（会被平台 trim）。

> 参考导出物里也有 2 行「第二天早上…」「第一桩…」以「第」起头，但那是**平台内已有正文**，不是导入器的切章对象；行内出现「第」的段落有 31 行，导出同样正常 —— 可见平台只对**行首**的「第」机械切章，加字转义针对的正是这一条。

**复跑与切换**（在集成工作区 `点子库/` 目录执行；脚本路径基于自身位置推导，无硬编码绝对路径）：

```sh
python 04-工具/build_txt_collection.py                        # 重建入库版（默认加字 ·）
python 04-工具/build_txt_collection.py --mapping              # 打印章号 ↔ 源文件对照
python 04-工具/build_txt_collection.py --include-appendix     # 末尾追加 8 篇资料
python 04-工具/build_txt_collection.py --reading --out X.txt  # 重建带目录的阅读版
python 04-工具/build_txt_collection.py --crlf --out X.txt     # CRLF 平台交换副本
python 04-工具/build_txt_collection.py --guard '※'            # 换加字（便于导入后批量替换）
python 04-工具/build_txt_collection.py --no-guard --out X.txt # 不加字，仅核对原文
```
