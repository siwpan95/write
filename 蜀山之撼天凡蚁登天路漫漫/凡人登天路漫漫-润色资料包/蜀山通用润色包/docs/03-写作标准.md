# 03 · 写作标准

这一册是"可判定的部分"。凡能写成数字和规则的，一律写死，避免每次重新商量。

---

## 一、字数口径（唯一）

> **汉字数 = 全文 Unicode 汉字（含章节标题行），不含标点、空格、数字、拉丁字母。**

- 下限：`config.json` 的 `min_han`，默认 **3000**。
- 目标区间：**3000—3300**。写到 3000 就停，不加句子凑。
- 计数工具：`tools/count.py`（不要用 Word 的字数统计，口径不同）。
- **不算数**：括号里的字、标点符号、数字、拼音、拉丁字母、空行。
- 反例：把"三千字"拆成 120 行，每行 25 字，其中 40 行是括号独白——Word 显示 3200，实到 1900。

## 二、格式硬标准

| 项 | 标准 | 检查 |
|---|---|---|
| 全角括号 | **0 个**（`（）`） | `count.py` 的"括号"列必须为 0 |
| 全角引号 | 必须配对（`“`数 = `”`数） | `count.py` 的"引号"列 |
| 半角标点 | 0 处（`,` `.` `?` `!` `;` `:`） | `count.py` 的"半角"列（数字小数点除外） |
| 连续标点 | 不允许 `，，` `。。` `！！` | `count.py` 的"连续标点" |
| 段落 | 一段一件事；平均段长 ≤ 20 字为宜 | `kit.py` 的"平均段长" |
| 章节标题 | 首行 `第126章 标题`（数字与标题间一个空格） | 目视 |
| 文件编码 | UTF-8（交付 txt 用 UTF-8 BOM） | `file` 命令 |

## 三、标点规范要点（GB/T 15834—2011）

只收长篇叙事最常错的十条：

1. **破折号** `——` 占两个字位置，不能断开；不用于替代冒号。
2. **省略号** 形式为 `……`（六点），占两个字位置；不与"等"并用。
3. **书名号** 只用于书、篇、报刊、文件、戏剧名；不用于单位名、活动名。
4. **引号** 内再用引号，外层双、内层单（`“他说‘好’”`）。
5. **顿号** 只用于并列词语之间；并列成分内部再有并列，用逗号分层。
6. **分号** 用于并列复句之间；单句内不要用分号。
7. **冒号** 提示下文，一句内不套两个冒号。
8. **问号** 无疑而问不用问号；连续问句各自带问号。
9. **句末点号** 引用整句且带冒号时，句号放引号内；否则放引号外。
10. **数字** 叙事文用汉字数字（三十二、七百），精确数据可用阿拉伯数字，但同一段内保持体例一致。

来源：GB/T 15834—2011《标点符号用法》（国家标准全文公开系统）。详见 `04-调研汇编.md`。

## 四、版式标准（冷叙事）

1. 一段一意，段与段之间空一行。
2. 单句成段是重型武器，一章不超过 15 处。
3. 对话独立成段，不写在段中。
4. 段首不空两格（成品 docx 由 `build.py` 统一加首行缩进）。
5. 不用分隔符（`***`）分节；用空行和一个短句过渡。

## 五、命名与交付

**草稿**：`draft/ch126.md`（一章一文件）

**交付件**：
```
<书名>-第126至127章-润色稿.md
<书名>-第126至127章-润色稿.txt     （UTF-8 BOM，给 Windows 用）
<书名>-第126至127章-润色稿.docx
```
单章时用 `--single`，生成"第130章"而不是"第130至130章"。

**入库**：docx 上传知识库（`config.json` 的 `kb_id`），文件名即上表。同名重复上传会带时间戳，旧版需人工删除（工具无删除权限）。

**不做**：整卷合并版。作者按批读，合并版反而不好定位。

## 六、docx 格式

| 项 | 值 |
|---|---|
| 正文 | 宋体 12pt，行距 1.6，首行缩进 0.74cm，段后 6pt |
| 章节标题 | 宋体 14pt 加粗，居中 |
| 书名行 | 宋体 14pt 加粗，居中，后面空 18pt |
| 页面 | 默认 A4，页边距不改 |

改这些值：`config.json` 的 `docx` 段。

## 七、三个"必须报备"的情况

交付说明里必须写清，不许默默处理：

1. **原文缺陷**：重复段落、时序冲突、数字不自洽、作者工作笔记残留、括号未闭合。
2. **改写决定**：把原文的一句话拆成两章、把某一章的收尾改到前一章、合并重复段落。
3. **未达标**：某章字数不足、某处没能补实、某段保留了原文的毛病（附原因）。
