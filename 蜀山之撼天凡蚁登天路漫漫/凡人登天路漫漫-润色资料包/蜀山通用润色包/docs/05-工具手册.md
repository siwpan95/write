# 05 · 工具手册

六个工具，各管一段。全部只依赖 Python 3 与 python-docx（可选，仅 build 需要）。

```
extract.py   取料   原稿 → 可读素材
count.py     把关   字数与格式，唯一口径
kit.py       体检   密度、重复、注水、节奏
build.py     出件   合成 md/txt/docx，可自动上传
upload.sh    单传   一个 docx 进知识库
selftest.sh  自检   四项全绿再开工
```

配置全部读 `config.json`，代码里没有硬编码的目录和书名。

---

## 一、extract.py —— 取料

```bash
python3 tools/extract.py 126              # 第 126 章（去括号、并段，一段约 4 句）
python3 tools/extract.py 126 --raw        # 保留原稿括号形态（看它坏在哪）
python3 tools/extract.py 126 --limit 2000 # 只看前 2000 字
python3 tools/extract.py 126 --src /path  # 换原稿目录
python3 tools/extract.py --scan           # 列全目录：章号、标题、文件、行号
```

识别三种标题写法：`# 第 126 章 标题`、`第126章 标题`、`## 第 126 章`。

**怎么用**：先 `--raw` 看一眼这章的括号病有多重，再抽干净版写。

---

## 二、count.py —— 把关

```bash
python3 tools/count.py draft/ch126.md
python3 tools/count.py draft/                     # 整目录
python3 tools/count.py draft/ch126.md --min 3200
python3 tools/count.py draft/ch126.md --json
python3 tools/count.py draft/ch126.md --quiet     # 只一行
```

输出列：

| 列 | 含义 | 合格 |
|---|---|---|
| 汉字 | 全文汉字（含标题） | ≥ min_han |
| 括号 | 全角括号数量 | 0 |
| 引号 | 左引号数/右引号数 | 相等 |
| 半角 | 半角标点数量（排除小数点、时间冒号） | 0 |
| 段 | 非空段落数 | —— |
| 连续标点 | `，，` `。。` 之类 | 0 |

退出码：`0` 全 PASS；`2` 有 FAIL；`3` 参数错误或文件缺失。

**注意**：`--min` 是临时提高门槛，不是降低理由。FAIL 时按 `docs/01` 四来源补实，不要加形容词。

## 三、kit.py —— 体检

```bash
python3 tools/kit.py draft/ch126.md
python3 tools/kit.py draft/ --top 12
```

六项：

| 项 | 看什么 | 经验阈值 |
|---|---|---|
| 密度 | 平均段长、短段占比 | 平均 8—20 字；短段 <35% |
| 重复 | 同一短句（≥6 字）出现 ≥2 次 | 0—1 处（复沓除外） |
| 注水 | 虚词高频（缓缓/淡淡/仿佛/一丝/忽然…） | 单词 ≤3 次 |
| 单调 | 段首词分布 | "他把"类不超过 15% |
| 节奏 | ≥60 字长句数 | ≤3 句 |
| 对话 | 含引号段落占比 | 8%—25% |

`kit.py` 只给建议，不判生死。它说"对白占比过少"时，要看这一章该不该有对话——库房查账的章可以一句对白都没有。

## 四、build.py —— 出件

```bash
python3 tools/build.py --start 126 --end 127
python3 tools/build.py --start 126 --end 127 --upload
python3 tools/build.py --start 130 --end 130 --upload --single
python3 tools/build.py --start 126 --end 127 --dir /other/draft
```

行为：
1. 按 `ch<号>.md` 依次读草稿；
2. 逐章校验（字数、括号），有不合格就停（`--force` 可强行出）；
3. 生成 `<书名>-第X至Y章-润色稿.md / .txt / .docx` 到 `out_dir`；
4. `--upload` 时调知识库上传脚本。

**单章**：`--start 130 --end 130 --single`，文件名是"第130章"而不是"第130至130章"。

**失败排查**：
- `缺草稿` → 文件名或章号不对（`ch130.md`，不是 `130.md`）
- `FAIL` → 先跑 `count.py` 看差多少
- 上传失败 → 检查 `kb_id` 与 `/sandbox/workspace/skills/ima-knowledge/scripts/upload_file.py` 是否存在

## 五、upload.sh —— 单传

```bash
bash tools/upload.sh /sandbox/workspace/xxx.docx
```

用于补传单个文件。批量出件请用 `build.py --upload`。

---

## 六、selftest.sh —— 自检

```bash
bash tools/selftest.sh
```

四项：
1. Python 与 docx 依赖；
2. 配置可读（书名、知识库、目录）；
3. `count.py` 对一份已知合格的样稿判 PASS、对一份已知不合格的判 FAIL；
4. `extract.py` 能取到你指定的一章。

有红项先修，不要带病开工。

---

## 七、常见输出与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 汉字 2997，差 3 | 写了 2997 就收笔 | 补一个具体动作或一个数，不要加"了""的" |
| 括号 2 | 引用了原文括号 | 按三落地改掉 |
| 引号 21/19 | 少一个右引号 | 找漏配的那句 |
| 半角 1 | 数字后用半角逗号 | 改全角 |
| 重复短句 x2 | 无意识的复沓 | 删一处，或改成两次不同语境 |
| 平均段长 45 | 长段过多 | 切段 |

## 八、目录约定

```
src_dir    原稿（只读，不要改）
draft_dir  草稿 ch*.md
out_dir    交付件
templates/ 表
samples/   对照
```

`uploads/` 下的原件**永不修改**。要改，改草稿。
