# 07 · 验证记录

本包在交付前做过一次完整实测。记录如下，供接手的人确认"工具是能跑的"，不是纸面文档。

测试时间：2026-11-23
测试环境：Linux / Python 3.12.13 / python-docx 1.1.2
测试数据：蜀山卷一 1—125 章、卷二 126—135 章（原稿 10 个 md 文件）

---

## 一、自检

```
$ bash tools/selftest.sh
== 1. Python 与依赖

  python-docx 1.1.2
== 2. 配置

  草稿目录：/sandbox/workspace/draft 存在
  下限：3000 汉字
== 3. count.py 判定能力
  合格样稿 → PASS
  不合格样稿 → FAIL 正确
== 4. extract.py 取章
  可识别章节：125 章
全部通过，可以开工。
```

说明：可识别 125 章是因为 1—10 章原稿已不在 `uploads/`（已处理完并清理），现存 11—135。工具本身工作在 11—135 全区间。

---

## 二、count.py 实测

```
$ python3 tools/count.py draft/ch133.md draft/ch134.md
ch133.md   汉字 3003  括号0  引号21/21  半角0  段303  PASS
ch134.md   汉字 3001  括号0  引号38/38  半角0  段326  PASS
合计 2 章，汉字 6004，不合格 0 章（下限 3000）
```

拦截能力：
- 全角括号：抓出（样稿含 4 个括号判 FAIL）
- 引号不配对：抓出（21/19 型）
- 半角标点：抓出（排除小数点和时间冒号）
- 字数不足：抓出（2997 判 FAIL）

---

## 三、kit.py 实测

```
$ python3 tools/kit.py draft/ch133.md --top 5
ch133.md  汉字3003  段303  平均段长9.9  短段29%  对话框18
高频词： 一点4  一种2  忽然2
段首高频： 因为5  没有4  他把4  他只4  所以4
  · 对白占比过少（6%）：冷叙事也要靠人说短话立人物。
```

这轮体检抓出一个真问题：`kit.py` 报"重复短句 x2"，查证是同一句"他把'雪'字写得正。"被写了两遍，已修正并重传该批。这是工具价值的实证——`count.py` 判 PASS 的章，`kit.py` 仍能发现问题。

## 四、extract.py 实测

```
$ python3 tools/extract.py 126 --limit 300
# 来源：蜀山 卷二-第126-130章（C1-记名）.md
开宗前一年，宗门要造一本名册。
...
$ python3 tools/extract.py 999
未找到第 999 章（检索目录：/sandbox/workspace/uploads）
```

- 三种标题写法（`# 第 126 章`、`第126章`、`## 第 126 章`）均可识别。
- 去括号、四句一段、对白独立成段均正常。
- 缺章返回码 3，不误报。

## 五、build.py 实测

```
$ python3 tools/build.py --start 133 --end 134 --upload
ch133    汉字  3003  括号0  OK
ch134    汉字  3001  括号0  OK
合计 2 章，汉字 6004
已生成：...-第133至134章-润色稿.md / .txt / .docx
上传中…upload success → ima_kb_UDyaN3jL
```

- md / txt（UTF-8 BOM）/ docx 三件齐出。
- 校验不过会停（不加 `--force` 不出件）。
- 单章用 `--single`，文件名不带"至"。
- 同名上传自动加时间戳，旧版需人工删（工具无删除权限）。

## 六、未纳入自动化的部分

这些靠人，不靠脚本：

1. **本章推进了什么**（结构判定）
2. **四来源的配比是否失衡**（工序/账目/履历/规矩）
3. **钩子是否成立、伏笔是否该埋**
4. **朗读是否顺**

`kit.py` 能给统计，给不了判断。判断在 `templates/章节体检表.md` 里，由人填。
