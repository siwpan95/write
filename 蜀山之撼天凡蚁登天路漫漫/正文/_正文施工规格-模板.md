# 施工规格 · 并行批次通用模板（可复用）

> **为什么有这份文件**：2026-11-17 卷二 C6–C10 曾用一份并行施工规格统一约束 5 个执行单元（零引号／每章 ≥2200／禁句表／「杨成志」每章 ≥2 次），效果极好——那 10 个循环（176–225 章，25.2 万字）是全书目前质量最稳的一批。**但那份规格是临时件，随施工结束而丢失，且 git 全历史从未提交过**（实测确认）。规格有效却没沉淀，等于下次并行施工要重新摸索。
>
> 本文件是它的复活版与通用化：**每次并行开工前，照此填一份，落进 `正文/`，随批次一起入库。**
>
> 依据（实测，非推断）：卷二 C11–C20 共 10 个循环 50 章的产物，规格条款遵守率 **10/10**——引号计数全为 0、每循环字数 11880–15786（折合每章 2376–3157）、「杨成志」每文件出现 10–50 次。

---

## 使用说明（照做，别跳）

1. **开工前**复制本文件到 `正文/_正文施工规格-<批次号>.md`，逐条填写下方「本批次取值」栏。
2. **填完入库**（`git add`），再让执行单元开工——**规格没入库不开工**。
3. **收工时**把实测值填回「实测」栏，与规格逐条对照。
4. **批次结束不删**——它是下一批次的起点，也是这一批次的证据。

## 二、执行单元须知（写进派工指令）

- **只写派工给你的那些章，不许越界**。若你在写的过程中发现相邻循环的章（例如本批只到 250，却顺手把 251 之后也写了），**一律删掉**——相邻循环有另一位执行单元在独立写，两边都写会内容打架与重复。**落盘前先数一遍章标题个数，必须正好等于派工章数。**
  > **实测事故（2026-11-18 卷二 C21–C25 批次）**：两个执行单元各多写了 5 章——C23 写了 241–245（属 C24）、C25 写了 251（属卷三 C1）。均由主控在落盘后核对发现并回退。**派工指令里必须写死"只写 N 章、不许写 N+1 之后"。**
- **按行号/段号删改必须限定在「章切片内」**。整文件行号删改会跨章误伤——2026-11-18 卷二批次实测：执行单元用整文件行号删重复段，误伤了同文件另一章的八段，而**字数达标、引号为 0、脚本全绿**，纯靠人工通读才发现。**删完必须逐段重读该章全文**，不能只跑计数。
- **「章内重复段」已进验收脚本**（`校验/验收_V2-C21至C25.py` 的 `find_dup_segments`），自测见 `校验/自测_段落去重检查.py`。判定口径：只查括号内的**叙述段**（对白回环是本书刻意手法，不判错）；实质字数 ≥12；**两次出现间隔 ≥8 段**才算机械复制（间隔大＝刻意回环，如 236 章那句在主角自述与于建追问后各落一次）。
- **单章篇幅不得畸变**。同批各章篇幅应大体相当（2200–2800）。出现 6000 字级的巨章，**不是"写得好"，是"没删干净"**——多半是把该分给下一章的铺陈写进了本章，或同一场景重复描写。卷末章尤其容易超：它要收束的东西多，但收束靠**动作与物件**，不靠篇幅。**落盘前对比同批其他章的字数，任何一章偏离同侪一倍以上都要回头压。**
- **先读规格再读章纲**，规格优先级高于章纲的措辞。
- **不确定时以规格为准**；发现规格与设定冲突，**停下来报，不要自行折中**。
- 每写完 1 个循环，**跑一次 §三 的验收命令**，不要攒到最后。
- 不引用任何未经证据包编号（F-xx）核实的外著细节；需要时按 `12` §3 的分级流程先补证据。

## 三、验收命令（收工必跑，逐批留痕）

```bash
cd <项目根>
# 1. 篇幅与禁用项自检（把 <glob> 换成本批次的正文文件模式）
python3 - <<'PY'
import glob, re, sys
files = sorted(glob.glob("正文/<本批次文件模式>"))
bad = []
for f in files:
    t = open(f, encoding="utf-8").read()
    body = re.sub(r"^#.*$", "", t, flags=re.M)
    n = len(re.sub(r"\s", "", body))
    q = t.count("“") + t.count("”")
    y = t.count("杨成志")
    hits = [w for w in ["系统","数据","状态","信息","用户","配置","版本","流程","指标",
                        "命运的齿轮","深邃的眼眸","嘴角勾起","邪魅","心头一颤"] if w in t]
    ok = (n >= 2000) and (q == 0) and (y >= 2) and not hits
    if not ok:
        bad.append((f, n, q, y, hits))
    print(f"{n:6} 引号{q:4} 杨成志{y:3} {'OK' if ok else 'NG'}  {f}")
print("批次结论:", "PASS" if not bad else f"FAIL {len(bad)} 项")
PY

# 2. 包级校验（每次提交前）
python3 校验/check_package.py          # 期望 error=0，结论 PASS

# 3. 哈希登记（新增/修改正文后必须重建，否则 MANIFEST 会失效）
#    见校验/check_package.py 的检查项 7
```

> ⚠️ **上一轮教训**：`MANIFEST.sha256` 曾整体失效（15 条路径失效、2 条哈希过期、28 个文件未收录），而 README 教的 `sha256sum -c` 一直在骗人。**新增或改名正文后一定要重建 MANIFEST**，否则包级校验会报错或（更糟）不报错但数据失真。
> ⚠️ **同批次里 MANIFEST 由主控统一重建一次即可**——多个执行单元各改各的容易互相覆盖；若你重建后发现条目数与他人报告的不一致，以主控重建的为准，不要反复争抢这个文件。

## 四之零、篇幅口径的**分层**（2026-11-18 实测发现）

**实测**：卷二 25 章的纯正文字数分布是**两段**的：

| 批次 | 章数 | 纯正文区间 | 中位数 |
|---|---|---|---|
| 卷二 C1–C20（2026-11-16～17 成稿，早期批次） | 20 | **3037–3720** | ≈3200 |
| 卷二 C21–C25（2026-11-18 成稿，按新口径） | 5 | **2200–2992** | ≈2600 |

即：**早期章系统性比后期厚约 600 字**。卷二有 14 章超 3000（181/186/189/194/211/216/218/219/156/157/168/170/171 等）。

**处置（已定）**：
- **C1–C20 不压**。这些章已封版、伏笔已咬合（门房那一竖、老周的布、火钳柄、半块饼等），为凑口径而删内容得不偿失。**该批不纳入 2200–3000 的验收范围。**
- **C21–C25 及以后（卷三起）统一用 2200–3000**。新章按新标准写，不受旧批影响。
- **不追溯**：口径分层是**向前生效**，不是回溯改判。

> **教训**：定量化口径前，先看**已封版内容的实际分布**。口径若比现存内容更严，要么压旧章（伤内容），要么分层（如本条）。**别让口径变成返工制造机。**

## 四之一、跨批机制交接（2026-11-18 实测事故）

**事故**：C24 的 244 章把「杨字那一竖为什么少」归因成**墨老旧、胶少、散得快**；而 C23（236–240）已定机制为**右手虎口的墨渗进纹路两年**、C25（246–250）更用「两张纸…都断在同一个地方」→「这就说明不是他今天的手坏了」**排除墨这个变量**——三章正面冲突。同一循环内也不自洽：241 章已写对「虎口那块墨渗进纹路两年了」，244 又换了说法。

**为什么脚本查不出来**：这是**语义层的归因冲突**，字数／引号／重复段／MANIFEST 全绿。

**流程防线（每个循环定稿后、下一个循环开写前，主控必做）**：
1. **机制清单**：本循环若写了「某个身体/器物导致某结果」的机制（如手、墨、纸、伤），把它记进**批内机制台账**，并写明"已埋章号"。
2. **下一循环开写前**：把上批机制台账逐条交给执行单元，规格里写"**该机制只能这样表述，不得另立归因**"。
3. **定稿前交叉核**：涉及既有机制的章，由主控逐条比对**已定稿章的原文**（不是凭印象）。
4. **执行单元若发现冲突，必须报主控，不得自行折中**——本轮正是执行单元主动报出才没漏过去。

> **判据：机制归因只能有一个，且必须与全链一致。** 若某章想另立归因，要么它确实是新信息（如本例 C25 用换左手验证），要么它就是错。

## 四之二、自检必须判**上下限**（2026-11-18 实测事故）

卷二 C21–C25 批次里，执行单元的自检脚本只判了 `n >= 2200`，**没判上限**，于是把 4804 字的章判成"达标"。**只判下限的自检是假自检。**

正确写法（用本项目现成的脚本，边界已写死）：
```bash
cd "D:/projects/repos/write/蜀山之撼天凡蚁登天路漫漫"
python3 校验/验收_V2-C21至C25.py     # 批量验收本批 5 个循环
# 或逐文件（注意必须判上限）：
python3 -c "
import re,sys
t=open(sys.argv[1],encoding='utf-8').read()
idx=[m.start() for m in re.finditer(r'^# ',t,flags=re.M)]+[len(t)]
for i in range(len(idx)-1):
    seg=t[idx[i]:idx[i+1]]
    n=len(re.sub(r'\s','',seg)); q=seg.count('“')+seg.count('”')+seg.count('「')+seg.count('」')
    y=seg.count('杨成志')
    print(f'{n:6}字 引号{q} 杨{y}  {seg.split(chr(10))[0][:30]}  {"OK" if 2200<=n<=2800 and q==0 and y>=2 else "NG"}')
" "正文/<你的文件名>.md"
```
**判定条件必须写全：`2200 <= n <= 2800 and q == 0 and y >= 2`**，并额外检查章标题个数正好等于派工章数、每章末行是「（本章完）」。

> ⚠️ `re.split` 带 2 个捕获组时，**步进是 3 不是 2**（`range(1, len(parts)-1, 3)`）。本轮验收脚本在此处踩过坑，一度把章数读成 10、字数读成 3 字，是执行单元发现的。
>
> ⚠️ **字数口径必须统一为「纯正文」**：不含章标题行与末尾「（本章完）」标记。原先按整段算，等于对每章多收一遍固定格式开销（约 18–35 字），口径不公平。
>
> ⚠️ **自测脚本必须复用验收脚本的判定函数**，不要各写一份——本轮自测与验收各写一份阈值，结果自测失准（人造样本没检出），这本身就是教训。

## 五、适用范围与边界

- 本模板是**项目内自用**件，与通用模板包（仓根同级目录 `通用模板包/`）的关系是：**模板包是指南，本件是本地化落地**。通用模板包给的是工序骨架与验收门，本项目在此基础上又长出了五章循环六幕法、「合即起」接力、零引号电波体、非空白全字符密度口径、禁句表等具体做法——**落地形态因项目而异，不必与模板包逐条对齐**。
- 批次级差异（字数口径、禁用项、接力接法）按批次填，**不追求全项目统一**；统一的是「填规格 → 入库 → 开工 → 验收 → 留痕」这条动作链。
