# 05 · 接口与文本族零件卡

> 接口族回答"主角一接入，世界立刻卡他什么"；文本族是接口最常见的载体。
> 字段定义见 `00`；来源逐条见 `99`。**均为 L1/L2 抽象，不含原书专名与数值。**

---

## `WB-IFACE-0015` 两层宪章争正统

| 字段 | 填写 |
|---|---|
| 零件名 | 两层宪章争正统 |
| 抽象层 | **L2** |
| 来源登记 | `SRC-006`（Tserena world-bible §14.1 两部宪章）｜提炼至 L2 |
| 借用方式 | 切断点：借"两套并存且互争正统的规则源"，自研切断点以下的具体条款 |
| 借用范围 | 借「习惯法与成文法并存、权力＝解释权、无第三方裁决者」；**未借**原作宪章名、国名、条款 |
| 双标签 | `组织·势力 × 施压`／`信息 × 催化` |
| 一句话定义 | 同一世界有两套都自称正统的规则源，任何决定都能找到依据，也都能被另一套推翻 |
| 层归属 | 基础层 |
| 可咬合零件 | `WB-INST-0001` 记录即存在（`制度隶属`）、`WB-HIST-0013` 焚卷旧账（`历史旧账`）、`WB-INFO-0017` 划名机制（`制度隶属`） |
| 落地接口 | `制度隶属`→ 两套权威机构；`历史旧账`→ 各自的正统来源 |
| 压力机制 | 想让决定生效须选一套宪章作依据（**权限**）；选了一套就得罪另一套（**代价**）；两边都对、互相否决（**矛盾**） |
| 行程激活差异 | 执法者读到「按哪套办」；投机者读到「择地起诉」；普通人读到「反正没我能选的」 |
| 不可申诉之物 | 没有第三方裁决者——两套宪章互不承认，不存在能终审的更高权威 |
| 施压就绪 | 是——主角第一次办事就被问"你按哪套" |

## `WB-INFO-0016` 名分阶梯（承认程度替代境界链）

| 字段 | 填写 |
|---|---|
| 零件名 | 名分阶梯 |
| 抽象层 | **L2** |
| 来源登记 | `SRC-001`（蜀山 03 §8.2 名分六阶）＋`SRC-004`（蜀山 03 §3.5 T-05 三档细化）｜提炼至 L2 |
| 借用方式 | 切断点：借"以被承认程度替代力量等级"的替换动作，自研阶梯档位 |
| 借用范围 | 借「阶梯量的是别人愿怎么称呼你、不是你能打多强」；**未借**原作六阶名称、顺序、特权细节 |
| 双标签 | `信息 × 施压`／`制度 × 阻碍` |
| 一句话定义 | 用"能被多少人说准名字／被承认到哪一级"作社会刻度，取代传统的力量等级 |
| 层归属 | 基础层 |
| 可咬合零件 | `WB-INST-0001` 记录即存在（`制度隶属`）、`WB-ECON-0012` 名分兑换率（`制度隶属`）、`WB-INST-0003` 职格互斥（`制度隶属`） |
| 落地接口 | `制度隶属`→ 承认机构；`制度隶属`→ 称谓可被核查 |
| 压力机制 | 想办事须达到相应承认级（**权限**）；降级即失去对应待遇（**代价**）；越接近顶层越接近被制度消耗（**矛盾**） |
| 行程激活差异 | 底层者读到「差一级」；上位者读到「要保持距离」；主角读到「有职无格」的错位 |
| 不可申诉之物 | 刻度由他人给，不能自评——自己再强也不会自动升一级 |
| 施压就绪 | 是——第一次办事就被问「你算几级」 |
| 适配基线 | 须重写：档位名称、晋升条件、各档待遇；**"刻度是承认不是力量"不得改** |

## `WB-INFO-0017` 划名机制（减法线）

| 字段 | 填写 |
|---|---|
| 零件名 | 划名机制 |
| 抽象层 | **L2** |
| 来源登记 | `SRC-001`（蜀山 押名／销名链）＋`SRC-004`（廓者 归档单语法／划销两行并存）｜提炼至 L2 |
| 借用方式 | 主题综合 |
| 借用范围 | 借「从记录中划线即抹除社会存在、旧行并存可追」；**未借**原作牌名、笔法、具体后果 |
| 双标签 | `信息 × 施压` |
| 一句话定义 | 划掉一个名字不等于涂改，而是让那个人在社会层面从未存在过，旧行仍留作证据 |
| 层归属 | 玩法层 |
| 可咬合零件 | `WB-INST-0001` 记录即存在（`制度隶属`）、`WB-INST-0002` 不可逆代价（`资源依赖`）、`WB-MECH-0004` 代价记账法（`制度隶属`） |
| 落地接口 | `制度隶属`→ 有权划名者；`资源依赖`→ 可查的旧行；`历史旧账`→ 划名前后的版本差 |
| 压力机制 | 想抹除某人须有划名权（**权限**）；划名必付不可逆代价（**代价**）；"抹掉他"与"还得有人记得他"相冲突（**矛盾**） |
| 行程激活差异 | 被划者读到「我从没存在过」；执法者读到「手续齐了」；后来者读到「两行并存＝有人动过」 |
| 施压就绪 | 否（减法线；须主角先入册，划名才落到他身上。留库待用） |
| 不可申诉之物 | 划名后不可自助恢复；旧行并存使"曾经存在"可被追查但不可复原 |

## `WB-ART-0019` 篡改痕迹符号系统（文本证物）

| 字段 | 填写 |
|---|---|
| 零件名 | 篡改痕迹符号系统 |
| 抽象层 | **L2** |
| 来源登记 | `SRC-018`（奇门遁甲旧案A §1.3）＋`SRC-004`（廓者 归档单语法）｜提炼至 L2 |
| 借用方式 | 即插即用后重写咬合：借"视觉符号编码篡改史"的运作逻辑，符号表全换 |
| 借用范围 | 借「不同痕迹标记不同性质的改动，读者/角色可读」；**未借**原作的具体符号含义与数量 |
| 双标签 | `器物 × 揭示`／`信息 × 催化` |
| 一句话定义 | 用一组可辨的视觉痕迹标记文本被改动的性质与时间，使文本差异成为可追责的证据 |
| 层归属 | 玩法层 |
| 可咬合零件 | `WB-MECH-0007` 描述即约束（`资源依赖`）、`WB-HIST-0013` 焚卷旧账（`历史旧账`）、`WB-INFO-0017` 划名机制（`历史旧账`） |
| 落地接口 | `制度隶属`→ 文本有法律效力；`资源依赖`→ 载体可被观察；`历史旧账`→ 旧版本 |
| 压力机制 | 想判断文本可信度须先读懂痕迹（**权限**）；误读即采信被篡改的版本（**代价**）；"可读"与"会读的人稀少"相冲突（**矛盾**） |
| 行程激活差异 | 档案员读到「哪页被动过」；篡改者读到「怎么掩盖」；当事人读到「有人替我担保过」 |
| 不可申诉之物 | 痕迹不可消除——只能被覆盖，而覆盖本身又留新痕 |
| 施压就绪 | 是——第一份文书到手就要判断「哪一页被动过」 |
| 适配基线 | 须重写：符号表、载体（竹简／纸／数据库日志）、各痕迹的含义 |

## `WB-IFACE-0018` 通电接口（主角一接入即被卡）

| 字段 | 填写 |
|---|---|
| 零件名 | 通电接口 |
| 抽象层 | **L2** |
| 来源登记 | `SRC-018`（项目 `13` 模板 §8.5 叙事接口＝通电的压力点）｜提炼至 L2 |
| 借用方式 | 自研（由项目内模板抽象而来） |
| 借用范围 | 借「空白不产生主角，只有被规则与矛盾通电的空白才可接入」；无外部借用 |
| 双标签 | `组织·势力 × 施压` |
| 一句话定义 | 一个可供主角接入的位置，必须立刻施加权限、代价或矛盾之一，否则只是布景 |
| 层归属 | 基础层（判定纪律） |
| 可咬合零件 | 所有其他零件——这是**元零件**，用于验收任何候选接口 |
| 落地接口 | 元零件不绑定特定承载物——它判的是**别的零件与位置是否已咬合**；落地时按被验对象取 `制度隶属`／`资源依赖`／`历史旧账` 至少一项 |
| 压力机制 | 想接入须付出权限／代价／矛盾之一（**权限／代价**）；三者皆无则接口不成立（**判定**） |
| 行程激活差异 | 不同探针接入同一接口，被卡住的点不同（这正是"可替换主角"的前提） |
| 不可申诉之物 | 三者皆无即不成立——不接受「氛围很好」「很有压迫感」作为接口成立的依据 |
| 施压就绪 | 是（本零件即通电检验器） |
| 接口四型 | **位置**（一个可去的场所）／**差事**（一件可接的活）／**身份**（一个可承的位）／**交易**（一次可做的交换）——判据不变：接入即被卡。**只找地点会漏掉后三型**（M-01 教训：卷四真正可接入的是「能写人」这个动作，池子只是条件） |
| 调用记录 | **M-01**／蜀山卷四 幻波池（376–380）／元零件判定通过／**实战发现接口需分四型（位置／差事／身份／交易）** |

## 接口族咬合示范

```
两层宪章争正统 ──制度隶属──→ 名分阶梯 ──信息──→ 划名机制
   （按哪套）                  （你算几级）        （划掉你）
        ↓                          ↓                  ↓
                篡改痕迹符号系统 ←── 焚卷旧账 ──→ 通电接口验收
                （谁动过文本）      （另一种结局）     （接入即被卡）
```

> **与模板 §1.5 的对接**：先锁课题 → 用 `WB-IFACE-0018` 判定候选零件是否真是接口 → 再按课题挑 2-3 件咬合 → 只为下一站拼装。**不是先把零件库用完。**
