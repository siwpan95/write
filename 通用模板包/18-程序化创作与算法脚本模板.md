# 18 · 程序化创作与算法脚本模板（v3.12 新增）

> **这份文件解决一个问题**：本包前 17 份模板默认"人来写、AI 辅写"，但程序化创作是一条独立且更古老的路线——
> 结构交给算法与脚本，血肉留给人与 AI。本文件把这条路**调研清楚、拆成可落地的算法槽位**，并给出随包可运行的三个脚本，
> 用来降低对 AI 的依赖度：素材组合、命名、场景推演这类"组合爆炸"工序，本不该烧 Token。
> **铁律**：算法管结构与约束，人管意义与情感。《宇宙巨校闪级生》证明了纯程序能堆出 1.7 亿字，也证明了那样堆不出故事。

## 一、调研综述（联网核实，访问日期 2026-11-13；来源逐条登记在 `14` §八）

### 1.1 中文谱系：一次提前二十年的实验

**《宇宙巨校闪级生》**（署名"紫峰闲人"）是中文网络最早出圈的**程序全自动生成**长篇网文，关键事实多源核对如下：

| 项 | 事实 | 来源交叉 |
|---|---|---|
| 上线 | 2007-02-25 于起点中文网，单日上传 1600 万字，后续累计放出约 3000 万字 | 公众号"老王聊网文"；橙瓜网 |
| 规模 | 规划 111 部 1111 卷，TXT 体量超 340MB，预估总字数 1.7 亿 | 百度百科；bilibili 作者自述帖 |
| 生成方式 | 作者用 VB 自写生成程序，除写程序耗时外，程序跑完全部内容仅 37 小时 | 同上 |
| 设定体量 | 1.7 万名有独立姓名/外貌/特长的人物；2.7 万种怪物；作者称底层可随机生成万亿级素材 | 同上 |
| 结局 | 不久即被起点下架封禁；仅前二十部完整流通，衍生第一人称版《蘑菇王子传》未放出 | 同上 |
| 学术提及 | 中国社会科学网《人工智能之于文艺创作的适恰性问题》将其列为网络文学机器写作案例 | cssn.cn |

**它的五个教训，直接变成本包的约束**（对照 `05` 去 AI 味五步、`11` §3.2）：

1. **堆字数≠讲故事**：词语与句式拼接可以无限产出，但没有叙事节奏、人物弧光、因果链——所以本包任何程序化产物**只进素材层（03/04/13），不直接进正文层（05/08）**。
2. **形容词泛滥是模板病的指纹**：逐器官堆砌外貌描写，正是无约束文法展开的典型输出——命名与描写文法必须配**去重 + 频次上限 + 验收门**。
3. **规模骗局不可复制**：1.7 亿字没有读者能读完，平台也会下架——程序化产能必须挂在 `02` 大纲的确定性结构上，而不是挂在前者上。
4. **可复现性是唯一护城河**：该作真正的遗产是"程序 + 素材库"可重跑、可变体（升级版/简化版/第一人称版）——本包脚本全部要求**固定种子（seed）可复现**。
5. **先于 AI 二十年，痛点未变**：程序可以无限堆字数与辞藻，难以编织情感内核——这正是今天 AI 写作的同一痛点，混合流水线（§三.5）因此成为默认解。

**同谱系的其他中文节点**（同为"模板 + 词库"路线，均早于或平行于大模型）：

- **狗屁不通文章生成器**（BullshitGenerator，GitHub menzi11，2019）：名人名言 + 承接句 + 点题句 + 转折句循环随机。价值不在文本，而在**证明了"句式文法 + 随机词库"足以骗过快速浏览**——这既是风险（低质水文，番茄 2026-05 起严打，见 `11` §1.4），也是"灌水检测器"的实现原理。
- **马尔可夫链文本生成**（约 20 行 Python 即可实现，见 ATYUN 技术文）：按词频接续，产出"像话但无主旨"的文本，适合做**文风基线对照**与低标准灌水检测。
- 各类**作诗机 / 藏头诗器**（更早的中文模板生成传统）：固定格律 + 词库替换，是"约束求解 + 文法展开"的民间版本。

### 1.2 西方谱系：五十年的方法储备

| 系统 / 事件 | 年代 | 方法内核 | 对本包的价值 |
|---|---|---|---|
| TALE-SPIN（Meehan） | 1976-77 | **目标驱动模拟**：角色有目标，程序模拟其问题求解，事件即叙事 | §三.3 场景模拟器的原型；"让角色自己撞出情节" |
| MEXICA（Pérez y Pérez） | 1999 起 | **投入-反思**循环 + 联想知识库，按"新颖度/趣味度"评估情节 | 情节候选**重排打分**的思路（§三.5 的重排步） |
| Brutus1（Bringsjord 等） | 1998-99 | 为单一主题（背叛）手工建模数学公式 | 领域狭窄但可控——单章/单情绪的程序化辅助 |
| Scheherazade（Riedl 等） | 2011 起 | 众包事件图 + 整数规划抽最优情节链 | 从素材库抽取**合法事件序列**的思路 |
| **NaNoGenMo**（Kazemi 发起） | 2013-今 | 每年十一月"写一个写出 5 万字小说的程序"；开源仓沉淀数千项目 | 民间方法大全；van Stegeren & Theune（ACL 2019）将其归纳为五类方法（见 §二表） |
| Tracery（Compton） | 2014 | 递归文法展开（JSON 文法 + 随机选择），Twitter 机器人标配 | §三.2 设定文法展开器直接采用此模型 |
| 游戏 PCG（Dwarf Fortress 历史生成、Caves of Qud 等） | 2006-今 | 程序化世界/人物/历史生成 + 玩家叙事 | `13` 区域包与 `03` 势力表的**批量预生成**思路 |

### 1.3 大模型时代：程序化没有死，它变成了流水线骨架

LLM 解决了"句子通顺"，但**长程一致性**仍是短板；程序化方法以骨架形式回归：

- **Re3**（EMNLP 2022）：递归重提示与修订——先让模型出结构化计划，再逐段生成时把计划与当前故事状态注入提示，对多个候选**重排**取连贯者，最后**修订**保事实一致。
- **DOC**：在 Re3 基础上加"详细大纲控制"（每个大纲节点带显式问题清单，写完必须回答）。
- **RecurrentGPT**（2023）：用自然语言的长期/短期记忆块模拟 RNN，逐步续写并更新记忆——本质是**把 `06` 最小台账自动化**。
- **Tree of Thoughts** 类搜索：对情节候选做多分支展开再回溯选择，对应 MEXICA 的重排思想。

结论：**这些流水线的每一步都能映射到本包既有模板**（§三.5 对照表）。程序化与 AI 不是替代关系：程序提供确定性、可复现、零 Token 成本；AI 提供语言流畅与语义判断；人提供意义与取舍。

## 二、方法谱系总表（五代方法 × 失效模式 × 本包对应）

> 依据 van Stegeren & Theune《Narrative Generation in the Wild: Methods from NaNoGenMo》（ACL 2019）的五分类，补第 5 代。

| 代 | 方法 | 代表 | 擅长 | 失效模式（必须防） | 本包对应 |
|---|---|---|---|---|---|
| 1 | 模板填空 + 词库随机 | 狗屁不通生成器、作诗机 | 形式文本、灌水、宣传语 | 重复冗余、无信息量 | 仅限：宣传语草稿、低质检测器 |
| 2 | 递归文法（Tracery 式） | Tracery、命名生成器 | 海量不重样的名字/地名/怪物/条目 | 形容词泛滥、语义冲突（"冰火狼"） | §三.1 / §三.2，喂 `03` `04` `13` |
| 3 | 统计接续（马尔可夫链） | 各类鸡汤生成器 | 模仿语感、文风基线 | 无主旨、前后矛盾 | 仅限：文风对照样本、去 AI 味参照 |
| 4 | 目标驱动模拟 / 搜索 | TALE-SPIN、Scheherazade、ToT | 情节候选、事件因果链、支线推演 | 机械、缺情感动机 | §三.3，喂 `02` L4 章纲与 `10` 节拍 |
| 5 | LLM 混合流水线 | Re3、DOC、RecurrentGPT | 初稿、扩写、重排、修订 | 幻觉、长程漂移、成本 | §三.5，挂 `06` 台账自动化 |

**启用判据**（满足任一才动程序化，否则手工或 AI 直出）：

1. **组合爆炸**：需要的素材量超出手工产能（人名 > 30、怪物 > 20、区域包 > 3）。
2. **结构确定**：工序规则可写成白纸黑字的判据（如 `02` §4.7 场景卡配额）。
3. **需要可复现**：同一设定要派生变体（简化版/第一人称版/番外）。
4. **需要批量巡检**：伏笔/时间线/用词频次的机械核对（挂 `06` §7.1）。

**禁用判据**（出现任一即停，退回人/AI）：

1. 黄金三章、中点、高潮等**情感节点**——算法产出只能当候补素材，禁止直接成文。
2. 需要价值判断、主题表达、人物弧光转折的段落。
3. 生成文本将**直接进入正文**而无人审（同时触碰 `11` §1.4 合规风险）。

## 三、五个算法槽位（每个含：算法 → 输入 → 输出 → 验收门 → 随包脚本）

### 3.1 槽位一 · 命名工厂（第 2 代：音节文法 + 去重）

- **算法**：声母/韵母或字素文法 + 权重选择 + 全局去重 + 固定种子。派生五类：人名、门派/势力、地名、怪物、功法/道具。字素库分 `--profile` 两套风格：xuanhuan（玄幻向，字素级组合）与 reality（现实向，**头槽位必须词组化**——单字组合会产出"国水/厂路"类断词，见 §七 v3.12.1）。
- **输入**：文风倾向（如玄幻/废土）、数量、种子。
- **输出**：带"构造说明"的名单（每个名字标注拆解来源，供反推修改）。
- **验收门**：① 重名率 0；② 抽 10 个人工判读，违和 ≤ 1；③ 与 `04` 已有人物卡、`03` 专名表**逐个查重**；④ 语义冲突专项（字素组合可能产生歧义词，须配黑名单过滤）。
- **随包脚本**：`tools/procedural/name_generator.py`。

### 3.2 槽位二 · 设定文法展开（第 2 代：Tracery 式递归文法）

- **算法**：`#符号#` 递归展开 + 随机分支 + 权重；一条文法 = 一个"设定生成器"（如怪物描述、区域包一句话、条目变体）。
- **输入**：JSON 文法文件（或内置演示文法）、起始符号、数量、种子。
- **输出**：展开后的设定条目草稿（**素材层**：进 `03`/`13` 的条目表，逐条人工过审后才编号入库）。
- **验收门**：① 同一符号展开 20 次，重复 ≤ 2；② 输出不得含自造专名冲突（与 `03` 专名表查重）；③ 每条过 `03` §2.1"可判定项"检查（不可判定的价值宣言类单独登记）。
- **随包脚本**：`tools/procedural/grammar_expand.py`。

### 3.3 槽位三 · 目标驱动场景模拟（第 4 代：TALE-SPIN 微缩）

- **算法**：角色持有目标与资源，按固定规则循环（缺物→寻物→取物→达成/受阻），每轮产出事件行；阻力项（障碍/失败率）由人预先配置——**情节是角色撞出来的，不是写出来的**。
- **输入**：角色表（目标/位置/持有物）、地点与物品表、障碍配置。
- **输出**：事件日志 → 人工改编成 L4 章纲一句话或 `10` 节拍候选。
- **验收门**：① 事件链有因果闭合（每事件有前置）；② 必须人工加"代价与情感动机"后才可入 `02`（呼应 `04` 欲望-恐惧三角）；③ 不得跳过 `10` 的 15 拍定位直接成文。
- **随包脚本**：`tools/procedural/goal_sim.py`。

### 3.4 槽位四 · 机械巡检（合规哈希账本）

- **算法**：对伏笔编号、时间线日期、专名/禁用词频次做正则与哈希比对——不是生成，是**确定性核查**。
- **挂接**：`06` §7.1 的 C1-C12 人工清单中，可机械化的项（专名一致性、伏笔编号闭合、字数/占比区间）交脚本；`tools/check_package.py` 的 C8 防回归断言就是此思路的包级实现。D-10 的 `consistency_audit.py`（包外，见 `14` D-10）属此类。
- **验收门**：脚本只出"风险与位置"，**不代改正文**（`11` 铁律同源）。

### 3.5 槽位五 · LLM 混合流水线（第 5 代：Re3 四步映射）

| Re3 步骤 | 本包对应工序 | 程序化增强点 |
|---|---|---|
| ① 结构化计划 | `02` L1-L4 + `10` 节拍表 | 计划为**人定或脚本校验**的结构化文件，不让 LLM 自由发挥 |
| ② 逐段生成 | `08` 章节创作 | 生成时注入：所在节拍、`06` 台账摘要、`05` 文风指纹参数 |
| ③ 候选重排 | `05` 500 字试写验收的推广 | 一次产 2-3 候选，按 `06` §四 三口径与文风阈值**机械初筛** + 人终审 |
| ④ 事实修订 | `06` C1-C12 + `11` 卷级体检 | 修订指令由巡检脚本产出（槽位四），LLM 只执行、不自判 |

**成本纪律**：流水线每一步都必须有"程序可判"的过/不过条件；判不了的地方才轮到 AI，判不了意义的地方才轮到人。

## 四、与既有模板的挂接表（只进素材层，不越权）

| 本包文件 | 程序化可喂给它什么 | 边界 |
|---|---|---|
| `03` 世界观圣经 | 文法展开的条目草稿、怪物/势力名单 | 逐条过审后编号回填；专名进 `03` 专名表 |
| `04` 人物卡 | 批量配角/龙套的名字与外貌底稿 | 主角与核心配角**禁止**程序化生成生平 |
| `13` 区域包 | 区域一句话、地标、遭遇表的批量变体 | 结构性矛盾（每图一条）必须人定 |
| `02` 大纲 | 场景模拟的事件候选 → L4 一句话章纲 | 代价、动机、弧光由人补 |
| `10` 节拍表 | 模拟事件对号入座候选 | 15 拍定位人判 |
| `06` 连载护航 | 台账自动更新、巡检报告 | 脚本不代改正文 |
| `05` / `08` | **不直接喂** | 程序化产物不得直接成正文 |
| `11` / `12` | 机械巡检报告、低质指纹检测 | 报告只给风险与选项 |

## 五、使用 SOP

```
1. 判定     → 过 §二 启用判据；不满足则 N/A（判"不适用"，非"未填完"，见 `00` §四）
2. 选槽位   → 组合爆炸类用 §三.1/§三.2；情节类用 §三.3；巡检类用 §三.4；成稿类用 §三.5
3. 固定种子 → 每次生成记录：脚本、参数、种子、日期、产出文件路径（登记进 `14` 或本书台账）
4. 过验收门 → §三 各槽位验收门逐条勾；不过的批次整批废弃重跑（不手补）
5. 人工过审 → 素材逐条判读后才进 `03`/`04`/`13` 编号入库；未过审素材隔离存放
6. 复盘     → 每卷末（`06` §11.3）检查：程序化产物占比、退稿率、是否该扩/缩使用面
```

**自检清单**：

- [ ] 每个程序化工序有书面判据（不是"凭感觉跑脚本"）
- [ ] 每个生成批次可复现（种子与参数已记录）
- [ ] 程序化产物 0 字直接进入正文层
- [ ] 专名已与 `03`/`04` 查重
- [ ] AI 生成标识合规已按 `11` §1.4 处理
- [ ] 不适用项标 `- [N/A]` 并写理由
