# 12 · 品类流派与 IP 合规前置模板（品类/IP 前置层 · v3.6）

> **本模板是两次真实纠偏的反面教材沉淀**：曾把"诸天无限-诸天"误判为"原创分类"→ 误判 IP 下架级风险；曾把"母亲灯下抬头"误判为"生死矛盾 P0 硬伤"。
> 根因都是**没联网核实品类常识 + 没逐字细读原文**。本模板把"先核实再下判断"固化成必跑前置。
> 何时用：定平台/分类时；正文用到他人 IP 元素（战锤/漫威/影视/游戏世界）时；被质疑 IP/品类时。
> **v3.6 适用范围声明（C6 / 上轮建议 5）**：本模板原只核「**他人 IP 版权**」与「语义挪用」。v3.6 起增设 §2.4「**原创设定的现实映射核查**」——**零侵权不等于零联想**：自创地名、纪年、格言、外语歌词仍可能撞真实地理／历史／语言／政治符号谱系。无平台／非连载项目：§1.1 平台分类与 §2.1 在架先例整体标 `- [N/A]` 并写明理由。

## 〇、三条铁律（前置，不过不往下走）

1. **品类常识先联网核实，禁止闭门造车式风险评估**——"原创分类/流派/同人惯例"必须查，不靠记忆拍脑袋。
2. **原文细节必须逐字细读再定性**——别把伏笔误判成硬伤；定性前先列全部相关行号互证。
3. **报告只给风险与选项，不代改正文**；法律灰色与行业惯例之差，明确标注"连载无需处理 / IP 开发时需换皮"。

## 一、品类/分类常识核查清单

### 1.1 平台分类定位（起点为例）

| 维度 | 核查问题 | 结论 |
|---|---|---|
| **一级频道性质** | 目标平台的一级入口叫什么？是「频道」还是「分类」？（起点按频道划分，如「诸天无限」为一级频道） | ＿＿＿ |
| **二级分类／流派** | 本书落在该频道的哪个二级分类下？（如诸天无限频道下分「诸天／无限／综漫／轻小说／短篇」） | ＿＿＿ |
| 本书落点 | 主频道 + 二级分类 + 可带标签（三者拼起来才是投稿时填的那一行） | ＿＿＿ |
| 同分类在架先例 | 搜"分类名 + 关键词"，在架规模？≥3 个在架实例 | ＿＿＿ |
| **分类沿革（防旧记忆）** | 该分类是否由别的品类拆分／改名而来？（如起点 2021-12-28 将「诸天无限」从科幻品类独立为一级频道） | ＿＿＿ |

> **事实注（v3.9 联网核实）**：起点中文网 2021-12-28 公告将原「科幻」品类拆分为「科幻」与「**诸天无限**」，诸天无限成为与玄幻／仙侠平行的**一级频道**，其下二级分类为「诸天／无限／综漫／轻小说／短篇」。因此「诸天流属于流派而非原创分类」的旧判断只对了一半：**诸天是二级分类（流派），而「诸天无限」是平台承认的一级频道**。定平台分类时必须把两级都说清，否则申报时会填错入口。同类沿革须逐平台核实（`12` §〇 铁律 1）。

### 1.1.1 各平台结构差异（v3.10 · 只写"结构类型"，不写死会变的分类名）

> 平台分类**名字**会变，**结构的维度**不会。所以本表只记"它按几个维度切"，不抄分类名——抄袭会过期的名单，等于制造下一条死链（`14` §四 保鲜期）。
> 确认度标注：`✅` 已核实（附来源）；`◐` 结构判断成立但未逐项核验分类名；**投稿前一律以站内当前导航为准**。

| 平台 | 切分维度 | 两级怎么填 | 易错点 | 确认度 |
|---|---|---|---|---|
| **起点** | **频道 → 分类 → 标签**（三级） | 一级填频道（如「诸天无限」），二级填分类（如「诸天」），三级挂标签 | 把二级分类当一级入口申报；忽略频道拆分沿革（见上条事实注） | ✅（`14` F-02） |
| **番茄** | **频道 → 分类标签**（无独立"分类页"层级） | 一级填「男生／女生」（另有有声书、出版书两个非网文赛道），二级从该频道分类标签里选主标签 | ① 把**标签**当分类填；② 分类页默认只展开男生频道，容易漏看女生侧；③ 主标签权重最高（约 60%），副标签别堆满 | ◐（一级四项已核；标签数量随版本变动） |
| **晋江** | **双维度**：性向站 × 原创性站 | 先定性向（言情／非言情），再定原创性（原创／非原创）；纯爱、百合、无 CP 归非言情侧 | ① 只填"言情"漏掉原创/同人维度，入口就错一半；② **同人站对 IP 更敏感**，先用 §2.1 三问法 | ◐（双维度结构确认；频道命名随改版调整） |
| **七猫** | **男频/女频 → 榜单驱动** | 一级填频道，二级靠"榜单位置"而非细分标签 | 按细分标签找"冷门蓝海"——该平台流量由榜单走，标签不是入口 | ◐（榜单派定位有行业分析支持） |
| **飞卢** | **题材标签驱动**（同人/动漫浓度高） | 一级频道 + 题材标签；同人元素占比高时先跑 §2.1 | 同人/二创元素多 → **IP 三问法必跑**，不能照"平台在架多"就放行 | ◐（结构判断，未逐项核） |

> **填法**：在本表选定平台后，回 §1.1 填五维（一级频道性质 / 二级分类 / 本书落点 / 在架先例 / 分类沿革），并注明核实日期。**没有核实日期的分类结论，一律视为未核。**

### 1.2 流派区分速查（易混点）

| 流派 | 核心机制 | 与大杂烩的关系 | 代表 |
|---|---|---|---|
| 无限流 | 主神/系统强制任务 + 奖惩 + 团战 PVP + 兑换强化 | 穿影视/游戏世界是常规 | 《无限恐怖》 |
| 诸天流 | 单机、无主神、主角唯一自由穿梭、自我经营 | **大杂烩本命**（穿武侠/影视/游戏/战锤皆可） | 诸天万界系 |
| 快穿流 | 更快的诸天（十几章一世界，偏女频） | 同诸天 | 快穿文 |

> 关键认知：**区分只在"有无主神级实体操控"，与"大杂烩程度"无关**。借用现成作品世界是诸天流惯例，非侵权信号。

## 二、IP / 同人合规核查

### 2.1 三问法（决定"连载要不要处理"）

1. **在架先例**：该 IP 的同人/缝合文在目标平台是否大量在架、正常连载？→ 搜"IP名 + 平台"取 ≥3 个在架实例。
2. **是否流派惯例**：本书所用该 IP 元素，是否属于所在流派的常规玩法（如诸天流穿战锤）？
3. **法律 vs 行业惯例差**：未授权同人商用仍属法律灰色；但**连载层面**行业惯例普遍放行，**仅在 IP 开发/出版时需换皮原创化**。

### 2.2 逐词核实表（用到的每个疑似专名填一行）

| 专名 | 是否历史公共符号（如双头鹰=拜占庭） | 是否 GW/厂商核心专名 | 连载风险 | 备注 |
|---|---|---|---|---|
| ＿＿＿ | 是／否 | 是／否 | 无需处理／需换皮 | ＿＿＿ |

### 2.3 换皮预案（仅在 IP 开发/出版时启用，连载阶段不碰）

- 每个核心专名备 2 个原创替换候选，保留"结构/权力关系"不变（见 `11` 模板 1.3）。
- 唯一可保留真实历史锚点的词：本身是公共符号、且作者已自写真实历史出处的（如双头鹰）。
### 2.4 原创设定的现实映射核查（v3.6 新增 / C6 / 上轮建议 5）

> **缺口**：§2.1~2.3 只核「他人 IP 版权」与「语义挪用」，未覆盖「**原创设定撞真实地理／历史／语言／政治符号谱系**」的表述风险。架空国家、自创格言、自造词、异化外语歌词都可能落在一条有确切文献的符号链上，从而改变读者的地理联想——这与版权风险是**两层**，不得混为一谈。

| 核查项 | 要问什么 | 证据要求 | 处置 |
| --- | --- | --- | --- |
| 地理／区域名 | 是否近似真实地名、区域称谓或争议地区？ | ≥2 个独立源，记录 URL 与日期 | 有意映射→登记；无意→改名或加设定说明 |
| 历史纪年／事件 | 自创年份是否恰好是真实敏感年份／事件年？ | 同上 | 微调年份，或明确标注「无影射意图」 |
| 语言／歌词 | 外语词形、格位、语法是否正确？是否撞真实国歌／口号？ | 母语者／权威语法源 + 版权状态 | 语法错必订正；撞车则改写 |
| 政治符号谱系 | 自创格言／三词口号是否落在有确切文献的符号链上？ | 概念史文献锚点 ≥1 条 | **概念史佐证 ≠ 作者意图**：只登记联想风险，不推定作者立场 |
| 命名学 | 人名／机构名词源是否指向真实族群／宗教／政党？ | 词源词典或语言学源 | 登记；必要时换词根 |

> **写法纪律**：本核查只输出「**风险 + 选项**」，不代改原文、不推定作者意图；结论须分层写明「版权风险」「语义／地理联想风险」「概念史佐证」三层。与 §〇 铁律 3 及 §四「联网核实 SOP（≥3 独立源）」一致。

## 三、原文细读纪律（防"伏笔误判硬伤"）

### 3.1 三遍读法规程

1. 定位：把所有相关行号列出（如"母亲灯下抬头"出现在第 21/23/26/398/399 行）。
2. 互证：逐行对照，判断是否自洽 / 是否构成伏笔闭环。
3. 定性：请作者拍板前，**不擅自给改文方案**；若判为伏笔，在报告里写明"正文已证·不回改"。

### 3.2 伏笔 vs 硬伤 判定表

| 信号 | 偏向伏笔 | 偏向硬伤 | **偏向制度张力（v3.6）** |
| --- | --- | --- | --- |
| 后文有明确点破／回收 | ✅ | | |
| 多处互文互证、非孤立 | ✅ | | |
| 仅两处表面冲突、无其他支撑 | | ⚠ 待查 | |
| 作者亲笔定性 | ✅ 闭环 | | |
| **程序空档／权限错配／两部并存，且原文未给协调机制** | | | ✅ **设计上故意的缺口**：登记为戏剧引擎，建议保留而非修补 |

> **与 `11` §2.1 同源**：本模板的「伏笔／硬伤」二分同样装不下制度张力，v3.6 起同步增设第三档；两处判定口径必须一致，避免一份报告里同一现象被判成两样。

## 四、联网核实 SOP（禁止脑补）

- **搜索词模板**：`平台名 + 分类名 + 在架/同人/缝合`；`IP名 + 平台 + 同人现状`；`流派名 + 定义 + 与无限流区别`。
- **源要求**：≥3 个独立源（平台站内搜索 + 行业文章 + 社区讨论），记录 URL 与日期。
- **输出**：把核实结论写进立项书/合规报告，附来源，避免"记忆型误判"复发。
