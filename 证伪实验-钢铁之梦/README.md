# 证伪实验 ·《钢铁之梦》

> **这个目录的用途不是收藏一部小说，是给一套方法论找反例。**
>
> 关联：`horror-motif-lab/` 的 `docs/07` 立了一条铁律「e₁ 全篇唯一」，
> 并在 `docs/10` 末尾自陈：**三例全是正例，缺反例，真正证伪需要一部「e₁ 明确漂了但仍然好看」的作品。**
> 本目录就是补这个缺口的实验场。

---

## 一、为什么选它

《钢铁之梦》三卷 + 番外，净正文 **69,632 汉字**（本次实测，原作自报 68,080，差额系统计口径含标记行所致），
158 页精装 PDF，附全部构建脚本。选它做靶子，不是因为它出名，是因为它的设定里有一句话：

> 「伊蒙·多诺万｜**不可靠旁白者，每章留一处自我更正**」
> —— `00_原作/源文本/卷一/part4.txt` · 附二 人物设定

按 `docs/07` 的字面读法，13 章 31 处自我更正 = 31 处「说的和实际不一样」，
这本书早该碎成奇观集锦。它没有。**这就是疑点。**

所以本实验不讨论「它算不算恐怖」（它不算，是新黑色西部），
只讨论一件事：**e₁ 到底是什么层的东西，允许漂到什么程度。**

```
03_盲读/                      甲／乙／丙 三份去标签文本（映射见表尾，先读文本再开）
99_工具/build_variants.py     从 00_原作 直接重建四个变体（按行号替换，未改行逐字节保留）
00_原作/                      只读原件，不再改动
  源文本/  卷一 卷二 卷三 番外（@@ 标记排版源）
  构建脚本/ 由原作提供，路径硬编码 /data/workspace
  成品_docx/ 可编辑主文件

```

**未入库**：四份成品 PDF（合订本 5.8MB + 单卷 3×1.9MB）。
理由：PDF 完全可由 `00_原作/源文本/` + `00_原作/构建脚本/` 重排再生，
而本仓 `.gitignore` 亦已拒绝 `.zip`；把 11.6MB 不可编辑二进制放进版本库，收益为零、克隆成本永久。
需要成品请向作者索取原始包。

## 三、来源与许可

- 来源：作者交付包 `钢铁之梦_全帙合订本_含源码.zip`（2026-11-21 收到，编成日期 2026-11-21）
- 解包注意：压缩包内文件名为 **UTF-8 但未置 UTF-8 标志位**，直接解压会得到乱码目录名；
  须用 `zipfile.ZipFile(..., metadata_encoding="utf-8")` 才正确。已实测：GBK 解码会抛 `UnicodeDecodeError`。
- 交付链接为腾讯云 COS 带签名地址（URL 内含 `q-ak`），**该参数未写入本仓任何文件**；本目录已扫描确认 0 处凭据。
- 本目录内容为**实验素材**，版权归原作者；此处仅作方法论研究留档，不再分发。

## 四、纪律

1. `00_原作/` 是**只读原件**。实验要在副本上做，原件一字不改。
2. 每次动正文之前，先在 `00_预登记` 里写清**预测和杀死阈值**，再动笔。
   顺序由 git 提交先后保证（预登记单独一个 commit）。
3. 评分口径不许中途修改；若中途发现口径有问题，**另立 v2 口径并重跑**，不覆盖旧结果。
4. 结论无论正负都写进 `02_评分与结论.md`，**包括「本实验设计有缺陷，不能定论」**这种结论。
