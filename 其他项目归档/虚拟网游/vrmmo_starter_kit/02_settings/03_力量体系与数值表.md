# 力量体系与数值表

> 网游文的读者是全网最会算账的一批人。**你写的每一个数字，都会被人拿去核。**
> 所以这套数值必须自洽：前后能对上，读者算得出来，作者不能临时改。

---

## 一、世界等级（全书唯一的成长轴）

### 1.1 升级需求

| 等级 | 升至本级所需经验 | 累计 | 解锁权限 |
|---|---|---|---|
| Lv.0 | — | 0 | 任务配置（1 位） |
| Lv.1 | 1,000 | 1,000 | 掉落配置 |
| Lv.2 | 1,000 | 2,000 | — |
| Lv.3 | 1,000 | 3,000 | 全服公告 |
| Lv.4 | 1,000 | 4,000 | 新地图·沉钟境 |
| Lv.5 | 1,000 | 5,000 | 封禁名单 |
| Lv.6 | 1,000 | 6,000 | 地图编辑 |
| Lv.7 | 1,000 | 7,000 | 副本导演 |
| Lv.8 | 1,000 | 8,000 | 版本公告 |
| Lv.9 | 1,000 | 9,000 | 现实接口 |
| Lv.10 | 1,000 | 10,000 | 续期申请 |

**每级恒定 1,000 点。** 不递增，因为递增会让后期读者失去"我能算出来"的参与感。

### 1.2 经验来源

| 行为 | 折算 |
|---|---|
| 玩家在线 | 1 小时 = 1 点 |
| 玩家完成任务 | 每个 = 5 点 |
| 玩家付费 | 每 1 元 = 0.5 点 |
| 玩家自发传播 | 按触达量折算（1,000 次曝光 = 2 点） |

### 1.3 每日上限（关键设定）

```
单日世界经验上限 = (当前世界等级 + 1) × 500
```

| 世界等级 | 单日上限 |
|---|---|
| Lv.0 | 500 |
| Lv.1 | 1,000 |
| Lv.2 | 1,500 |
| Lv.3 | 2,000 |
| Lv.4 | 2,500 |
| Lv.5 | 3,000 |
| Lv.6 | 3,500 |
| Lv.7 | 4,000 |
| Lv.8 | 4,500 |
| Lv.9 | 5,000 |

**30 天上限合计：27,500 点。** 升级只需 10,000 点，余量 17,500——也就是说，**主角允许失败几天，但不能连续失败。**

这条设定解决了三个问题：
1. 防止"拉一百万玩家一夜满级"的崩坏
2. 制造"今天额度用完了，只能等明天"的节奏压力
3. 让"抢时间"成为常态：每天 0 点前必须把额度打满

### 1.4 与正文的核对

| 章节 | 世界等级 | 当日上限 | 实际情况 | 是否自洽 |
|---|---|---|---|---|
| 第 3 章 | Lv.0 | 500 | 314 点（312 人 × 约 1 小时 + 任务） | ✅ |
| 第 4 章 | Lv.0→1 | 500 / 1,000 | 314 → 1,000（增长 686，未超上限） | ✅ |
| 第 17 章 | Lv.3 左右 | 2,000 | 论坛炸了，十万人涌入，但当日只能吃 2,000 | ✅ 制造"热度不等于等级"的张力 |
| 第 28 章 | Lv.9 | 5,000 | 100 万在线，单日打满 5,000 | ✅ |

## 二、资源池（主角的钱包）

### 2.1 收支模型

| 项目 | 数值 |
|---|---|
| 初始余额 | 3,800 |
| 发布任务 | 扣除标定的奖励额度 |
| 任务完成回收 | 支出 × 0.6（净亏 40%） |
| 升级奖励 | +800 × 新等级 |
| 玩家付费 | 每 1 元 = 0.5 点 |
| 临时调整（爆率/复活时间/刷新间隔） | 每次 200–500 点 |

### 2.2 为什么设计成"净亏 40%"

因为这是真实的活动预算模型：**你发出去的福利，永远不会 100% 转化成留存。**

这个 40% 的窟窿，逼着主角必须不断找新的资源来源——升级、氪佬、活动收入。这就是全书的经济引擎。

### 2.3 一个算账示例（第 4 章保卫战）

```
战前余额              800
临时调整（刷新间隔）  -400
─────────────────────────
战后余额              400

任务奖励用的是"修理券"（铁匠铺库存），不是资源池支出
所以这一夜，江砚没有回收任何资源

→ 第 4 章结束时，他其实是"现金流紧张"状态
→ 这就是第 5 章他必须去找新资源来源的动机
```

**写数值的最高境界：让数字自己生出剧情。**

## 三、玩家七维数据

后台能看到的七项指标。每一项都对应一种写作功能：

| 维度 | 含义 | 写作功能 |
|---|---|---|
| 付费意愿 | 0–100 | 判断谁可以被"礼包"拉回来 |
| 在线时长 | 累计小时 | 判断谁是真爱 |
| 流失风险 | 0–100% | **最常用**：数字下降 = 情感浓度上升 |
| 投诉倾向 | 0–100 | 制造"这个人马上就要闹事"的预警 |
| 社交影响力 | 0–100 | 决定谁能当"意见领袖"（小小鱼、沈迟） |
| 操作水平 | 0–100 | 决定战斗中的表现（刀哥 92，新手上路 8） |
| 内容产出力 | 0–100 | 决定谁能把热度带出去（小小鱼 95） |

**用法示例：**

> 新手上路｜死亡次数：9｜流失风险：**0.2%**

一行数据，比一段抒情有力。这是本书最核心的写作技巧之一：**用后台数据代替心理描写。**

## 四、回收程序判定

```
冗余度 = 基础值 2.0%
       + 未交互时长（小时）× 0.25
       - 今日交互人数 × 0.8

清理条件：冗余度 > 3.5%
单次清理上限：本世界冗余总量的 5%
执行时间：每日 00:00
```

**算例：**

| 对象 | 未交互时长 | 今日交互人数 | 冗余度 | 结果 |
|---|---|---|---|---|
| 周启山（第 3 章） | 12h | 0 | 2.0 + 3.0 = 5.0% | 清理 |
| 周启山（第 4 章后） | 1h | 87 | 2.0 + 0.25 − 69.6 → 取 0.3% 下限 | 保留 |

读者可以自己算，算完会脊背发凉——**因为这意味着"每天必须有人跟每一个 NPC 说一句话"。**

## 五、游戏内数值（九垓）

### 5.1 等级与区域

| 区域 | 等级区间 | 对应世界等级 |
|---|---|---|
| 灰鸦境（灰鸦镇） | 1–20 | Lv.0–3 |
| 沉钟境 | 21–40 | Lv.4–6 |
| 盐海境 | 41–60 | Lv.6–8 |
| 中垓三境 | 61–80 | Lv.8–9 |
| 上垓三境 | 81–100 | Lv.10 |

### 5.2 装备品阶

白（普通）→ 绿（精良）→ 蓝（稀有）→ 紫（史诗）→ 橙（传说）→ **金（唯一）**

**金装的特殊规则**：每个世界每一件金装只能存在一把。老周在第 4 章打的那十二把剑标注为"白"，但因为"由原住民亲手打造"，系统给了隐藏属性。

### 5.3 战斗基础值（Lv.1）

| 属性 | 玩家 | 野猪 | Lv.3 怪 |
|---|---|---|---|
| 生命 | 100 | 80 | 300 |
| 攻击 | 10 | 12 | 35 |
| 防御 | 2 | 3 | 12 |
| 复活时间 | 10 秒（可调至 3 秒） | — | — |

**核对第 2 章**：小小鱼 −12 被打翻（生命 100，一下 12，合理）；刀哥 −31（木棍击打耳根，暴击，合理）；新手上路 −1（Lv.1 打 Lv.1 未命中要害，合理）。

## 六、数值设计五条原则

1. **所有数字必须能被读者手算。** 不能出现"增长了 37.6 倍"这种没人验证的表述。
2. **上限比增量重要。** 有上限才有节奏，没上限就是崩坏。
3. **每次变强必须付出可见的代价。** 调爆率花资源，发补偿亏 40%，封号结仇。
4. **数值服务于情绪，不服务于爽。** "流失风险 0.2%"比"+999 攻击"更能让人心跳。
5. **不许临时改数。** 如果剧情需要更多资源，让角色去挣，不要让系统白送。

## 七、给写作者的速查卡

```
世界等级：每级 1000 点，上限 (等级+1)×500/天
资源池：初始 3800，净亏 40%，升级 +800×等级
玩家七维：付费 / 时长 / 流失 / 投诉 / 影响力 / 操作 / 产出
回收判定：冗余度 > 3.5% → 删
权限 = 世界等级（永远相等）
公告 = 契约（说了必须做到）
```
