# 开书全流程 SOP（可复用）

> 这是一套"从扫榜到成稿"的作业流程，任何题材都可以套。
> 每个阶段都标注：**输入 / 工具 / 产出 / 验收标准 / 常见坑**。
> 全部工具在 `05_tools/`，零第三方依赖，Python 3.9+ 直接跑。

---

## 阶段 0 · 准备工作（30 分钟）

| | |
|---|---|
| **输入** | 无 |
| **产出** | 一个空目录 + 一份"我不写什么"清单 |
| **做法** | 先排除：① 我不懂的行业（写不了细节）② 平台红牌题材 ③ 我读不下去的类型 |

**为什么要先做"排除"：** 网文最大的浪费不是写错，是写了 20 万字才发现自己不喜欢这个题材。写到第 100 章还在硬撑的书，100% 会崩。

---

## 阶段 1 · 扫榜取数（2–4 小时）

| | |
|---|---|
| **输入** | 起点分类榜 / 番茄分类榜 / 七猫榜单 |
| **工具** | 手工或用浏览器插件把榜单存成 CSV |
| **产出** | `05_tools/data/rank_samples.csv` |
| **验收** | 至少 40 条样本，含书名 / 分类 / 标签 / 热度 / 字数 |

**字段规范（必须统一，否则脚本跑不动）：**

```csv
platform,category,title,author,tags,words_wan,status,heat,heat_type,snapshot
起点,游戏·游戏异界,万朝之劫,余弦公式,"历史游戏;游戏异界;万订",0,连载,15196,月票,2026-09
```

**常见坑：**

- ❌ 只抓"最好的 10 本"。要抓 40–50 本，因为你要看的是"腰部在写什么"，不是"头部写了什么"。
- ❌ 标签只填分类。标签要填**作者自己打的标签**，那才是差异化信息。
- ✅ 一定要记录**快照时间**。三个月后你会需要知道这个数据是哪天的。

## 阶段 2 · 赛道分析（1 小时）

```bash
cd 05_tools
python3 rank_scan.py --input data/rank_samples.csv \
        --out-md ../01_report/_auto_rank_stats.md \
        --out-json data/rank_stats.json
```

| | |
|---|---|
| **产出** | 三张表：平台×分类分布 / 标签饱和度 / 独占标签清单 |
| **验收** | 能回答三个问题：① 哪个子类样本最多？② 哪个标签已过载？③ 哪些作品靠"独占标签"挤上榜？ |

**读表要点：**

1. **"样本多"不等于"好进"。** 样本多说明有读者，也说明有对手。
2. **"饱和度：极高（红海）"不等于不能写。** 它只说明"用同一个标签，你进不去"，必须找一个独占标签。
3. **独占标签表最有价值。** 它列出的每一本，都是"靠一个别人没有的钩子"活下来的。挨个拆它们的开篇。

## 阶段 3 · 选题立项（2 小时）

### 3.1 出 3 个候选方案

必须来自三个不同方向，不能是同一个点子的三个变体：

- 一个"顺赛道"的（最稳，保底）
- 一个"逆赛道"的（差异化，有风险）
- 一个"跨赛道"的（把别的类型的能力搬过来）

### 3.2 打分

```bash
python3 hit_score.py --input data/candidates.json --sensitivity \
        --out-md ../01_report/_auto_hit_score.md
```

| | |
|---|---|
| **产出** | 三方案六维打分 + 命中率 + 短板诊断 |
| **验收** | 最高分方案的"最短的板"是否 ≥ 4 分？如果不是，先想清楚怎么补 |

**打分纪律（很重要）：**

- 每个维度打分必须写一句"依据"。没有依据的分数是自我安慰。
- 差分不要超过 1 分。如果你给方案 A 打 5、方案 B 打 2，说明你在选之前就想好了。
- 一票否决项要诚实勾选。勾了不丢人，写完 20 万字才发现才丢人。

### 3.3 定题卡

输出 6 项：**书名 / 一句话卖点 / 类型标签 / 目标平台 / 目标字数 / 对标作品 + 差异化**。

## 阶段 4 · 设定（1–2 天）

| | |
|---|---|
| **产出** | 世界观设定集 / 人物小传 / 力量体系与数值表 |
| **验收** | ① 每条设定都能回答"它逼主角做什么选择" ② 数值能被读者手算 ③ 每个角色有一个"记忆点动作" |

**三条铁律：**

1. **设定不是背景板，是冲突制造机。** 写不出"它制造什么冲突"的设定，删掉。
2. **数值必须有上限。** 没有上限的成长 = 没有节奏 = 读者失去期待。
3. **配角必须会添乱。** 每 5 个角色里至少 2 个在关键时刻给主角制造麻烦，否则全是工具人。

---

## 阶段 5 · 大纲（1 天）

### 5.1 节拍表（每章一行）

```bash
python3 outline_build.py --config data/book_config.json \
        --out-md ../03_outline/_auto_beat_sheet.md
```

每章填 5 个字段：**章号 / 一句话事件 / 爽点类型 / 章末钩子 / 目标字数**。

**填不出来 = 这章是水。** 这是最有效的注水检测器。

### 5.2 体检

```bash
python3 outline_build.py --config data/book_config.json --check
```

自动检查 4 条：

- R1 连续 3 章爽点类型相同 → 审美疲劳
- R2 某章没有钩子 → 读者在这里跳出
- R3 单章字数偏离均值 40% → 节奏忽快忽慢
- R4 黄金三章爽点重复 / 缺钩子 → 开头废了

### 5.3 段落级细纲

黄金三章单独做，精确到"第几段干什么、多少字、交付什么"。

**参考 `03_outline/02_黄金三章细纲.md`。**

## 阶段 6 · 写正文（每天 1–2 章）

### 6.1 写作节奏

| 阶段 | 每天 | 说明 |
|---|---|---|
| 前 3 章 | 1 章 / 天 | 慢，因为要定调。这三章会决定后面 300 章的语感 |
| 4–30 章 | 2 章 / 天 | 存稿期，目标是攒够 10 万字再发 |
| 上架后 | 2 章 / 天 | 稳定比爆发重要 |

### 6.2 每章开写前问三句

1. 这一章读者能拿到什么？（信息 / 爽点 / 情感 / 悬念，至少一个）
2. 章末的那一句是什么？（先想结尾，再写开头）
3. 有没有一段我自己会想快进？（有就删）

### 6.3 写作时的三个硬规矩

- **一段不超过三句。** 手机屏幕一屏 12 行，超了就被划走。
- **不用"他明白了""这意味着"。** 结论让读者自己得。
- **情绪不靠形容词。** "非常感人"删掉，换成一个具体动作或数字。

## 阶段 7 · 润色与过审（每章必做）

### 7.1 引号规范化

```bash
python3 fix_quotes.py ../04_manuscript/*.md
```

中文正文里出现英文直引号 `"` 是硬伤，读者一眼看出不专业。

### 7.2 体检

```bash
python3 prose_lint.py --input ../04_manuscript/第XX章_xxx.md
```

输出 8 项指标 + 三级风险词 + 套话清单。

| 指标 | 参考区间 | 不达标怎么办 |
|---|---|---|
| 正文字数 | 2,800–4,000 | 不足就补一个"动作段"，不要补描写 |
| 平均段长 | ≤ 90 字 | 拆段 |
| 对话占比 | 30%–55% | 低于 20% 说明在"自嗨叙述"，把一段说明改成两个人吵架 |
| 平均句长 | ≤ 32 字 | 长句拆短 |
| 章末留手 | ≥ 2 个信号 | 补一个未完成的动作或未兑现的信息 |
| P0 词 | 0 | **改设定，不是改词** |
| P1 词 | 0 | 改词 |
| 套话 | ≤ 2 处 | 逐条替换 |

### 7.3 过审的真相

**词表只能挡住 60% 的风险，另外 40% 在设定层。**

三条自查：

1. 我的世界观里有没有"封建迷信核心设定"？（有 → 改成架空体系）
2. 有没有真实企业 / 城市 / 机构 / 名人？（有 → 全部虚构）
3. 有没有"游戏化的违法行为"？（有 → 换任务类型）

## 阶段 8 · 发布与复盘

### 8.1 发布节奏（起点）

| 节点 | 动作 |
|---|---|
| 存稿 10 万字 | 开书，日更 2 章 |
| 满 3 万字 | 申请签约 |
| 上架前 | 准备"上架感言"，写清这本书要写什么 |
| 首订日 | 加更，兑现承诺 |

### 8.2 三个关键数据

| 数据 | 看什么 | 及格线 |
|---|---|---|
| 前三章读完率 | 开头是否成立 | 越高越好，掉得最狠的那一章就是问题章 |
| 追读率 | 内容粘性 | 稳定不跌 |
| 书架比 | 读者是否愿意留下 | 收藏 / 阅读 |

### 8.3 复盘（每 10 万字一次）

回答四个问题：

1. 哪一章的追读掉得最狠？为什么？
2. 哪个角色被读者提到最多？为什么？
3. 我最近 10 章用了多少次同一个爽点？
4. 如果现在重写第一章，我会改什么？

**第 4 个问题的答案，就是下一本书的起点。**
