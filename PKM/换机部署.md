# 换机部署

> **目标**：在新机器上从零到可用，**一条命令**。
> 前提只有两个：**Node 22+** 与 **Python 3.9+**（其余全自动）。

## 一键部署

```bash
# Git Bash（Windows）
git clone https://gitee.com/siwpan/write.git
cd write
bash tools/bootstrap.sh
```

```powershell
# Windows PowerShell / PowerShell 7
git clone https://gitee.com/siwpan/write.git
cd write
powershell -ExecutionPolicy Bypass -File tools\bootstrap.ps1
```

脚本做四件事，每步都有明确输出与失败原因：

| 步 | 动作 | 幂等 |
|---|---|---|
| 1 | 环境自检（Node / Python / git） | ✅ |
| 2 | 装 Node 依赖（cordis 等；`node_modules/` 不入库） | ✅ 已装则跳过 |
| 3 | 重建 PKM 索引 + 图谱 + MOC（约 10 秒） | ✅ 覆盖重建 |
| 4 | 跑闸门 `npm run check` | ✅ |

**退出码**：`0` 部署成功 ／ `1` 环境不满足 ／ `2` 某一步失败。

可选参数（PowerShell 版）：

```powershell
.\tools\bootstrap.ps1 -SkipInstall   # 跳过 npm install
.\tools\bootstrap.ps1 -SkipCheck     # 跳过闸门
```

## 环境要求

| 依赖 | 版本 | 用途 | 缺失后果 |
|---|---|---|---|
| **Node.js** | ≥ 22 | Cordis 编排层（`tools/host.mjs`） | **硬依赖**，脚本中止 |
| **Python** | ≥ 3.9 | PKM 内核 + 检查器（零三方依赖） | **硬依赖**，脚本中止 |
| git | 任意近期版本 | 版本同步 | 警告，不阻塞 |
| Obsidian | 可选 | 图形化双链/图谱视图 | 不影响任何功能 |

安装：

```powershell
winget install OpenJS.NodeJS
winget install Python.Python.3.12
```

## 为什么能这么快部署

设计上刻意避开了所有「重依赖」：

1. **Python 内核零三方依赖** —— 只用标准库，不需要 `pip install`，
   也就没有「装包失败」「版本冲突」「网络拉不动」这类换机常见故障。
   （与本仓既有 49 个 `.py` 同源纪律。）

2. **`node_modules/` 不入库** —— 由 `npm install` 从 `package-lock.json` 复原，
   锁定版本，可复现。

3. **派生产物可重建** —— `PKM/index.json`（17MB 倒排索引）不入库，
   10 秒重建。入库的只有知识资产（图谱 / MOC / 原子笔记），天然跨机一致。

4. **零硬编码路径** —— 脚本一切相对仓根定位；Python 解释器按
   「显式配置 → 环境变量 → PATH → 常见安装位置」逐级探测，
   不写死盘符与用户名。

## 可选：加装 Obsidian（图形外壳）

本仓是纯 Markdown，**Obsidian 可以直接以仓根为 vault 打开，零迁移**。

1. 装 Obsidian（<https://obsidian.md>）
2. `Open folder as vault` → 选本仓根目录
3. 首次会提示信任并激活仓库内插件 —— 建议**先不装社区插件**，
   核心功能（搜索 / 双链面板 / 图谱）原生就有

配置建议（大仓性能）：

| 设置 | 建议值 | 理由 |
|---|---|---|
| Files and links → Excluded files | `node_modules`、`审校报告`、`PKM/index.json` | 减小索引压力 |
| 核心插件 | 关「关系图谱」（全局） | 全局图谱对 1000+ 文件意义不大，用局部图谱 |
| 社区插件 | 装 `Omnisearch`（若嫌原生中文搜索弱） | 中文分词增强 |

> **注意**：`node_modules/` 会被 Obsidian 索引 —— 务必加入 Excluded files，
> 否则启动会明显变慢。

## 跨机一致性

| 内容 | 同步方式 | 一致性保证 |
|---|---|---|
| 正文 / 设定 / 素材 | git（Gitee + GitHub 双端） | 提交历史 |
| PKM 知识资产（图谱 / MOC / 原子笔记） | git | 提交历史 |
| 索引缓存 | 本地重建 | 可复现（同一输入同一结果） |
| Node 依赖 | `npm install` | `package-lock.json` 锁版本 |

> **行尾差异提醒**（沿用《工作区规范》§八 3 的既有结论）：
> 全局 `core.autocrlf=true` 的机器工作区是 CRLF，未设的机器是 LF。
> 这是**环境差异，不是仓库缺陷** —— 索引内容 100% LF 归一。
> 但如果你要对工作区文件做哈希，请按 **blob** 字节算：
> `git cat-file blob HEAD:<path> | sha256sum`。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot find package 'cordis'` | 未装 Node 依赖 | `npm install` 或重跑部署脚本 |
| `ERR_MODULE_NOT_FOUND` | Node 版本 < 22 | 升级 Node |
| `未找到 Python` | 未在 PATH | 装 Python（勾选 Add to PATH），或设 `WRITE_PYTHON` 环境变量 |
| `检查器未按协议输出 JSON` | Python 内核崩溃 | 看 stderr；多半是 Python 版本 < 3.9 |
| 检索无结果 | 索引未建 | `npm run pkm:build` |
| 闸门报断链 ERROR | 新写的 `[[链接]]` 目标不存在 | 修正链接；`PKM/断链清单.md` 有明细 |

指定 Python 解释器（任何平台）：

```bash
export WRITE_PYTHON=/path/to/python    # bash
$env:WRITE_PYTHON = 'C:\Python312\python.exe'   # PowerShell
```
