# MOC · 原子笔记索引

> **原子笔记**＝Zettelkasten 的最小知识单元：**一块乐高只装一个想法**。
> 判定标准：**这条能独立搬到别的项目里用吗？** 能，才是原子笔记；
> 不能，它还只是某本书的设定条目（那些留在各自的 `bible/` 里）。

## 收录标准

一条内容要不要立为原子笔记，看三条：

| # | 标准 | 反例（不该收录） |
|---|---|---|
| 1 | **跨项目可移植** —— 换个项目还成立 | 「赵海是本书主角」→ 留在本书 bible |
| 2 | **一块乐高只装一个想法** —— 一句话能说清 | 「本书的创作方法论」→ 太笼统，拆 |
| 3 | **可追溯** —— 能指到原文出处 | 凭印象总结 |

三条全中才收录。**宁缺毋滥** —— 原子笔记的价值在于每条都能复用，
一旦掺进只对本项目有用的内容，整份笔记的迁移性就毁了。

## 新增一条的流程

1. 先问三条收录标准，全中才立。
2. 在 `PKM/00-原子笔记/` 建文件，命名 `atom-NNNN-<主题>.md`（NNNN 顺延，**不复用**）。
3. 写 frontmatter：`id` / `title` / `type` / `status` / `created` / `projects` / `tags`。
4. 正文五段：**事实 → 为什么值得抽出 → 可操作推论 → 关联 → 出处**。
   「出处」段必须指到**文件 + 章节**，可追溯才算知识资产。
5. 在本索引表加一行；在 [[PKM/01-MOC/MOC-跨项目知识网络.md]] §二 方法论清单加一行。
6. `npm run pkm:build` → `npm run check`（断链须为 0）。
