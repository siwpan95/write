# MOC · 合规／审校维度

> **为什么单独建**：23 份合规/审校文档是**机械门禁**的落点，
> 平均入链 1.52（全仓最高，但仍只有项目 MOC 的通用锚定）。
> 本仓的核心纪律是「**能自动判定的不靠人记**」——
> 这个维度值得单独成页，才能看清哪些事已被机器守住、哪些还靠人。

## 一、已机械化的门禁

| 检查 | 工具 | 判据 |
|---|---|---|
| 双端同步 | `tools/checkers/sync_check.py` | 落后＝ERROR／不可达＝WARN |
| PKM 连接层 | `tools/checkers/pkm_check.py` | 断链＝ERROR／孤立>5%＝WARN |
| 编码与格式 | `tools/fix_bom.py` | 内容类带 BOM、机器读类不带，全库 LF |
| 清单完整性 | `npm run manifest` | MANIFEST.sha256 失配＝失败 |
| 项目结构一致性 | consistency 检查器 | 章号/章名/尾标/字数 |
| 产物失配 | `tools/bootstrap.*` 第 6 步 | `git diff --quiet -- PKM/` |

## 二、人工审校（尚未机械化，也不该全机械化）

| 事项 | 判据 | 原子笔记 |
|---|---|---|
| 设定与正文冲突 | 看改动成本由谁承担 | [[atom-0015 以正文为准]] |
| 已冻结卷发现问题 | 进「补漏任务表」而非修订清单 | [[atom-0008 冻结与不回改前文]] |
| 设定集定期体检 | 季度四步审计 | [[atom-0017 四步审计 ＋ 五权矩阵]] |
| 工具测不了的部分 | 器读尺内，人读尺外 | [[atom-0016 双读规程]] |

> **一条边界**：按 [[atom-0016 双读规程]]，
> 工具能量「断链/编码/字数」，量不了「这两部作品是不是真同宇宙」。
> 后者必须由人写进**项目关联登记表**与**原子笔记** ——
> 这也是本仓「受控登记（人工输入）＋ build（机器消费）」分层的依据。
