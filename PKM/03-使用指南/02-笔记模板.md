# 可直接抄的原子笔记模板

> **用法**：复制下面「模板本体」整段 → 另存为 `PKM/00-原子笔记/atom-NNNN-你的标题.md`
> → 改 `id` / `title` / `created` → 填正文 → 双链 → 跑 `npm run pkm:build`。
>
> **不需要模板时**：本文件本身就是一份**合规的原子笔记实例**（可直接当样板改）。

---

## 模板本体（复制这段）

```markdown
---
id: atom-NNNN
title: 一句话标题（与文件名一致，便于双链解析）
type: 永久笔记
status: 草稿
created: YYYY-MM-DD
projects: [作品A, 作品B]
tags: [方法论/主题, 口径/维度]
---

# 一句话标题（与文件名一致）

> **原子笔记**：这块乐高是什么、解决什么问题 —— 一句话，说清「哪本书里已经用了它」。

## 事实

这里写**已经成立的东西**：机制是什么、规则怎么定的、数值是多少。
每个关键句后面带出处标记 `〔文件路径 §章节〕`。

（写不出来？说明这条还没想清 —— 先留 `status: 草稿`，别急着标稳定。）

## 关键机制

1. **机制一**：怎么运作的。
2. **机制二**：边界条件 —— 什么时候**不**成立。
3. **机制三**：和谁冲突 / 替代什么。

## 适用边界

- ✅ **适用于**：什么场景、什么题材、什么阶段。
- ❌ **不适用于**：什么情况**别**套用这条。
- ⚠️ **注意**：容易被误用的地方。

## 出处

- `项目/路径/文件.md` §某章节 —— 为什么这么定
- `项目/路径/另一文件.md` —— 实证案例

## 复用记录

- 2026-XX-XX ｜ `项目/文件.md` §某节 ｜ 用于某具体施工点 —— 有效 / 待复核
```

## 字段说明（七个必填 + 一个建议）

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `id` | ✅ | `atom-NNNN` | **永久唯一，创建后不改** —— 改了断链。下一个可用编号查 `PKM/00-原子笔记/` 现有最大号 +1 |
| `title` | ✅ | 文本 | **与文件名一致**（去掉 `.md`），便于双链解析 |
| `type` | ✅ | `永久笔记` / `文献笔记` / `临时笔记` / `指南` | Zettelkasten 三型 + 指南 |
| `status` | ✅ | `稳定` / `草稿` / `待复核` | **没落定的别标「稳定」** —— 标错会导致后续复用踩坑 |
| `created` | ✅ | `YYYY-MM-DD` | |
| `projects` | ✅ | 列表 | 涉及哪些作品；**空列表 `[]` ＝ 跨项目通用** |
| `tags` | ✅ | 列表 | 受控词表，见下 |
| `复用记录` | 建议 | 段落 | 笔记正文的一节（非 frontmatter）。**空着也行，但用过的必须补** |

### 受控标签词表（照着用，别自造）

| 前缀 | 含义 | 例 |
|---|---|---|
| `设定/` | 设定类 | `设定/共享宇宙`、`设定/人物` |
| `口径/` | 判断规则 | `口径/创作`、`口径/合规` |
| `方法论/` | 做事方法 | `方法论/模板`、`方法论/题材` |
| `体系/` | 设定体系 | `体系/四神`、`体系/境界` |
| `IP/` | 版权与合规 | `IP/战锤40K` |
| `资产/` | 资产类型 | `资产/跨项目` |
| `指南/` | 使用说明 | `指南/PKM` |

> **为什么必须收敛**：标签是检索入口。历史标签 137 处、有效只覆盖 6 个文件 ——
> 不收敛就退化成噪音。

---

## 三档 `status` 怎么选（最常被写错的一栏）

| status | 什么时候用 | 含义 |
|---|---|---|
| `稳定` | 已被**至少一次实际复用**验证过 | 可以放心拿去用在别的项目 |
| `草稿` | 刚写下，想法还没想透 | 还没验证过，别当结论用 |
| `待复核` | 曾经用过但**用不了 / 结论被推翻** | **最容易被忽略的一档** —— 不改这档，后续会持续踩坑 |

> **实测教训**：`status` 写成「稳定」但实际用不了，比没有笔记更糟 ——
> 它会让下一次复用直接信任一条假结论。**用不了就改档，不要装作没事。**

## 落位与命名

| 项 | 规则 |
|---|---|
| **放哪** | `PKM/00-原子笔记/atom-NNNN-标题.md` |
| **文件名** | `atom-NNNN-简短标题.md` —— 标题进文件名，检索时标题命中 ×3（实测） |
| **不收的东西** | 只对本项目有价值的设定条目 → 留在那本书的 `bible/`，**不要**立原子笔记 |
| **已有文件要补 tags** | 走 `PKM/02-索引/文档元数据清单.md` 旁挂，**不改正文** |

## 写完立刻跑

```bash
npm run pkm:build     # 重建索引 + 图谱 + MOC
npm run pkm:doctor    # 自检
npm run check         # 闸门：ERROR 0 = 可放行
```

然后看 `PKM/孤立文档清单.md` —— 新笔记是否已脱离孤立。
