# 工具资产台账治理（统一登记而非物理搬迁）

> **原子笔记**：一条**工程治理技术**——当工具散落多处时，用"统一台账 + 门禁"根治，而不是物理搬家。
> 与 [[atom-0002 通用模板包]] 同属方法论层，本篇管**工具资产的登记与防漂移**。

## 事实

工具的"多点开花"有两个不同问题，常被混为一谈：
1. **找不到**（认知问题）——不知道已有工具、不知道哪个是权威源 → 重复造轮子；
2. **位置散**（物理问题）——脚本分布在不同目录。

**关键洞察**：解决问题 1 不需要解决问题 2。物理搬迁会断三类链，代价远高于收益：

| 断链类型 | 实证案例（本机 @SIWPAN 2026-11-23） |
|---|---|
| 适配器硬编码引用 | `点子库/04-工具/audit_consistency.py` 被 `consistency_check.py:31`、`cordis.yml:122`、`12-checker-consistency.mjs:24` 三处指向 |
| 脚本间相对 import | 钢铁之梦 `build_omnibus.py` 用 `import build as B` 复用卷一脚本 |
| 自包含包"解压即用" | 通用模板包 / 零件库 / horror-motif-lab / vrmmo kit 的 README/SOP 写死包内工具路径 |

## 做法（四步）

1. **四类判定**：D 软件源码 → B 包内随包工具 → C 作品生产脚本 → 剩下才是 A 通用工具。拿不准按 C 处理。
2. **统一台账**：一份机器可读的清单（如 `tools/TOOLS_MAP.md`），全量登记每个脚本的路径、分类、调用方、权威源。
3. **落地规则**：A 类新工具一律进仓根 `tools/`；B 留包内、C 留作品目录、D 不算工具；新增/删除必须同步台账。
4. **门禁防漂移**：脚本实时扫描 vs 台账登记比对，未登记 / 已删除 / 分类段数量漂移即 FAIL（`tool_registry_check.py`，可挂 npm script）。

## 为什么有效

- **认知统一**：一处可查全仓工具与权威源 → 解决"找不到/重复造轮子"；
- **零断链**：不物理搬迁 → 三条链全保住；
- **防复发**：门禁让"新增脚本不登记"变成机械可检的 ERROR，而非靠人自觉；
- **可移植**：换机只要重跑扫描脚本即可重建台账视角，不依赖某台机器的记忆。

## 边界

- 台账是**本机时点快照**（脚本数、引用行号），换机/增删脚本后须复跑门禁更新；
- 台账登记 ≠ 代码质量门禁——它只管"有没有登记、分类对不对"，不检查脚本能不能跑；
- 真正跨项目复用的前提是 A 类工具本身设计得好，台账只解决"找得到"。
