## 为什么值得单独抽出

六栏结算制规定了「卷完要回填六栏」，但**没有留痕机制就无法验证回填是否真做了**。
修订记录补的正是这一环：

| 六栏结算 | 工作区修订记录 |
|---|---|
| 规定「回填什么」 | 证明「回填了」 |
| 分散在各补遗章 | 集中成一张**单调递增的账** |
| 内容层 | 审计层 |

**三个设计细节特别值得学**：

1. **「每卷追加一行」而非「改表」** —— append-only，历史不可覆盖。
   与 [[atom-0008 冻结与不回改前文]] 同源。
2. **「达两处引用后入术语表」** —— 术语入典有**明确阈值**，
   避免一个新词刚出现就被写进术语表（然后没用几次就废了）。
3. **回填检查逐条打勾，且含白名单核验** ——
   每次结算都要重新确认「有没有跑出白名单之外」。

## 与本仓工具链的对应

这套账本在本仓的 PKM 层有同构实现：

| 点子库 | 本仓 PKM 层 |
|---|---|
| 工作区修订记录 r1/r2/… | git 提交历史 |
| 回填检查 | `npm run check` 闸门 |
| 白名单核验 | `sync` / `pkm` 检查器 |
| 术语入典阈值 | 受控登记表的收录三标准 |

差异也值得记：git 是**机器自动**留痕，修订记录是**人工判断**留痕。
按 [[atom-0016 双读规程]] 的说法 —— git 是「器读」，修订记录是「人读」，
**两者互为交叉验证**，缺一不可。
