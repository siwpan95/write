# 文档元数据清单（受控 · 人工维护）

> **用途**：给**已有的** Markdown 补充元数据，而**不修改文件本身**。
>
> **为什么需要它**：本仓 1161 个已有文件**不批量注入 frontmatter**
> （违反《工作区规范》§五「正文零改动」，且会让正文改动与笔记改动混在一起无法审计）。
> 需要给某篇文档补 `tags` / `aliases` / `type` 时，在这里登记一行，
> 索引器合并进图谱 —— 源文件一个字节不动。
>
> **格式**：JSON Lines（每行一个 JSON 对象），便于逐行追加与 diff。
> 字段全部可选；未登记的字段以索引器自动判定为准。

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `path` | ✅ | 仓相对路径（正斜杠） |
| `type` | | 文档类型（正文／设定／台账／报告／模板／总览／工具） |
| `tags` | | 标签数组（受控词表，见使用指南） |
| `aliases` | | 别名数组（用于 `[[别名]]` 链接解析） |
| `projects` | | 归属作品数组 |
| `note` | | 登记理由（人读，可追溯） |

## 登记示例

```jsonl
{"path": "廓者未名夜/03-世界观圣经-廓者未名夜.md", "tags": ["设定/世界观", "体系/四神"], "aliases": ["廓者世界观圣经"], "note": "跨宇宙核心设定，应可被 atom-0001 直接引用"}

```

## 维护纪律

- **只登记「跨项目有意义」的文档** —— 单项目内部的元数据由目录语义承担，不必登记。
- **一条一行** —— 便于逐行追加、逐行 diff、逐行删除。
- **别名不要与已有标题冲突** —— 同名歧义会被判为断链（宁可断，不可错）。
- 登记后跑 `npm run pkm:build` 生效，再跑 `npm run check` 确认无新断链。
