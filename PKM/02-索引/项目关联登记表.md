# 项目关联登记表（受控 · 人工维护）

> **用途**：登记**项目之间**的真实关联，由 `npm run pkm:build` 据此给项目 MOC
> 自动补上「相关项目」互链。
>
> **为什么不硬编码在 MOC 里**：MOC 是**生成物**，手写内容会被覆盖；
> 关联关系是**会变的知识**（今天同宇宙，明天可能拆开），必须有独立的、
> 可 diff、可追溯的登记处。
>
> **登记什么**：只登记**真的共享了什么**的关系 —— 共享设定、共享方法论、
> 共享研究。若只是「题材相邻」，**不要登记**（见 MOC-跨项目知识网络 §四
> 的说明：题材相邻 ≠ 设定共享，硬连会让 MOC 退化成噪音网）。
>
> **格式**：JSON Lines（每行一个 JSON 对象）。

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `from` | ✅ | 源项目名（一级目录名） |
| `to` | ✅ | 目标项目名 |
| `kind` | ✅ | 关系类型：`共享设定` / `共享方法论` / `共享研究` / `同宇宙` |
| `shared` | | 具体共享了什么（一句话说清） |
| `constraint` | | 随之而来的**硬约束**（如有） |
| `note` | | 登记理由／出处 |

## 维护纪律

- **只登记真共享** —— 题材相邻不算共享（理由见 MOC-跨项目知识网络 §四）。
- **共享必须有具体载体** —— `shared` 字段要写清「共享的是哪份设定／哪套方法」，
  写不出具体载体 = 这不是真共享，别登记。
- **硬约束要记** —— 若共享带来约束（如去 GW 化必须同步），写进 `constraint`。
- **双向登记** —— 关系是双向的，两边都写，保证从任一端都能走到。
- 登记后跑 `npm run pkm:build` 生效，再跑 `npm run check` 确认无新断链。
