# 失效条目登记表 · 受控 JSONL（旁挂）

> **作用**：把「保留原文作过程留痕、不再作为判据」的**散文失效标记**变成机器可读登记。
> 来源：`华夏克苏鲁/02_设定与参考/资料包索引与引用规范.md:4`（第三轮订正提示，2026-11-11）。
> **纪律**：本表**旁挂**，资料包原文一字不改（守《工作区规范》§五「正文零改动」）；
> 每条 `status=deprecated` 的条目在 `npm run pkm:search` 输出中会被标注 `deprecated_sections`。
> **粒度说明**：失效的是**段落/结论**，不是整篇文档 —— 故检索侧只提示、不做整篇降权，
> 避免误伤同一资料包内仍然有效的其他结论。
> 建立：2026-11-14（v2 审计 G-06）｜ 格式校验：`tools/checkers/rules_check.py` R-05

## 字段契约

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `DEP-NNN`，唯一 |
| `file` | 是 | 仓相对路径，须在 `PKM/index.json` 中存在 |
| `section` | 是 | 失效结论所在节号 |
| `claim` | 是 | 被撤回的结论（原样摘录，不改写） |
| `status` | 是 | 固定 `deprecated` |
| `reason` | 是 | 撤回理由 |
| `superseded_by` | 是 | 替代判据（≥1 条，须指向 `01_bible/` 或勘误台账） |
| `source` | 是 | 失效声明出处（file:line） |
| `registered` | 是 | ISO 日期 |

> 新增失效条目时：① 追加一行 JSONL；② 跑 `npm run metrics:check` 与 `npm run check`；
> ③ 在 `资料包索引与引用规范.md` 的订正提示里补一行指向本表。
