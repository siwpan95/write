# 专题维度登记表（受控 · 人工维护）

> **用途**：登记**横跨所有项目**的知识维度，由 `npm run pkm:build`
> 据此为每份专题 MOC 自动生成「全仓文档地图」区块。
>
> **为什么需要这张表**（本轮实测得出的维护债）：
> `MOC-文风维度.md` 手写了 22 条文档链接。文档增减、改名、
> 新项目加入时都要人工改 MOC —— 漏改就是断链或遗漏，且**没人会发现**。
> 与「题材簇登记表」同样的道理：**关系是会变的知识，必须有独立可 diff 的登记处**。
>
> **两层共存**（复用题材簇的标记区间机制）：
> - 专题 MOC 里的**人工叙事**（维度分析、Why、关联）→ 手写，生成器不碰
> - 「全仓文档地图」区块 → `<!-- pkm:begin 文档地图 -->` 标记区间，由本表驱动
>
> **格式**：JSON Lines（每行一个 JSON 对象）。每个 `id` 对应一份
> `PKM/01-MOC/MOC-<id>.md`（如 `文风维度`、`人物角色`）。

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 专题 MOC 文件名后缀（不含 `MOC-` 与 `.md`） |
| `name` | ✅ | 维度名（人读） |
| `match` | ✅ | 路径匹配用的**正则**（对仓相对路径匹配，大小写不敏感） |
| `groups` | ✅ | 分组定义：数组，每项 `{title, match, note}` |
| `exclude` | | 排除正则（避免误抓） |
| `intro` | | 该维度的「为什么单独建」一句话 |

## 维护纪律

- **新增维度**：写一行 JSONL ＋ 建一份 `MOC-<id>.md`（含标记区间），
  跑 `npm run pkm:build` 生效。人工叙事写在标记区间**之外**。
- **改匹配规则**：`match`／`groups.match` 用正则，改完跑 build 看
  「全仓文档地图」是否如预期，**再跑 `npm run check`** 确认无新断链。
- **避免误抓**：务必设 `exclude`（至少排除 `审校报告|tools/pkm|PKM/`），
  否则构建产物会被自己抓进去。
- **组内不建知识链**：地图区块用 wikilink 指向真实文档（真实导航关系），
  但**组内成员彼此不因「同维度」而互连** —— 同题材簇的纪律。
