# 题材簇登记表（受控 · 人工维护）

> **用途**：登记**题材相邻但不共享设定**的作品簇，
> 由 `npm run pkm:build` 据此生成跨项目 MOC 的「题材簇」区块。
>
> **与「项目关联登记表」的区别**（这是本表存在的理由）：
>
> | | 项目关联登记表 | 题材簇登记表（本表） |
> |---|---|---|
> | 记什么 | **真的共享了什么**（共享设定/方法论） | **只是题材相邻**（都写无限流、都写废土） |
> | 要不要建链 | **要** —— MOC 里出「相关项目」互链 | **不要** —— 只做归类，不建知识链 |
> | 举例 | 廓者 × 战锤42（同宇宙） | 廓者 × 战锤42（都写同人衍生） |
>
> **为什么题材簇不建链**：题材相邻 ≠ 设定共享。
> 硬连会让 MOC 退化成「看起来都相关」的噪音网 ——
> 读者在 MOC 里找的是「这些真的有关」，不是「这些都写网文」。
> 按 [[atom-0003]] 的口径，共享语汇**只记账不避让**，但**记账不等于互链**。
>
> **格式**：JSON Lines（每行一个 JSON 对象）。

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 簇标识（kebab-case） |
| `name` | ✅ | 簇名（人读） |
| `members` | ✅ | 成员项目名数组（须是真实的一级目录名） |
| `common` | ✅ | 共同特征（一句话说清「为什么归一簇」） |
| `distinct` | ✅ | **各成员为何仍是独立作品**（这一栏最关键） |
| `note` | | 补充说明／辨析陷阱 |

## 维护纪律

- **`distinct` 栏必填且必具体** —— 写不出差异，说明它其实是「共享设定」，
  该去「项目关联登记表」而不是本表。
- **簇内成员不建知识链** —— 本表只驱动 MOC 的归类展示，不产生 wikilink 互链。
  真正要连的，去「项目关联登记表」。
- **成员名必须是真实一级目录名** —— 否则 MOC 里会出现指向不存在项目的条目。
- 登记后跑 `npm run pkm:build` 生效，再跑 `npm run check` 确认无新断链。
